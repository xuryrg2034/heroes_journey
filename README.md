# Ashen Oath — Дорога к башне

Браузерная кампания на TypeScript, Vite и PixiJS: кот-варвар проходит лесное обучение, штурмует ворота, выбирает путь через три комнаты замка и сражается с колдуном. Последовательные цепочки ударов, ключи и двери на поле, объявленные атаки, переносимый запас расходников и выбор наград.

Художественный стандарт новых персонажей — [Character Art Style Guide](docs/character-art-style.md): выразительный мультяшный dark fantasy с угловатыми формами, толстым тёмно-синим контуром и простым cel shading. Все 18 типов персонажей и живых предметов получили PNG-иллюстрации в этом стиле; исходные изображения находятся в `public/art/characters/`, промпты — в `artifacts/art-prompts/characters.json` и `artifacts/art-prompts/chapter-finale.json`.

## Запуск

```sh
npm install
npm run dev
```

Откройте адрес Vite, обычно http://localhost:5173.

```sh
npm run build
npm run preview
```

## Поход

На титуле сначала предложены [три базовых урока](docs/levels/tutorials.md) и [три боя лесной тропы](docs/levels/forest-trail.md) с устройствами, затем [четыре боя к опушке](docs/levels/advanced-trail.md) с холодом, прыжком, третьим цветом и стрелком, [три боя с провалами](docs/levels/pit-trail.md), [Тюремщик и две ветки](docs/levels/chapter-finale.md); после них — семь испытаний: **Лесной лагерь, У главных ворот, Оживший пир, Караульная, Шахматный зал, Запретная библиотека, Башня колдуна**. Любая сцена запускается одним нажатием без замков прогресса. Лес открывает прежний трёхволновый бой «Незваные к завтраку», ворота — начало похода, остальные пункты — прямой вход в выбранную комнату.

Каждый выбор начинает свежую сцену с 5 HP и 0 энергии. Прямой вход в комнаты замка и башню даёт по одному холоду, бомбе и лечению; огня в стартовом запасе нет. Энергию для прыжка можно получить обычной цепью. «Повторить комнату» возвращает состояние входа в выбранную сцену.

Пункты списка используют стабильный seed 701. «Повторить комнату» и «Поход сначала» сохраняют текущий seed; другой seed можно передать через debug `loadScenario`. Обычный экран выбора не требует технических параметров.

- **Ворота, поле 6 × 10:** 12 боевых убийств вызывают командира с ключом. Заберите ключ либо нанесите воротам суммарно 200 урона. Проходите через ворота цепочкой — отдельной кнопки входа нет.
- **Залп:** каждые три хода стрелы поражают заранее отмеченные клетки. За ход до залпа показываются конкретные цели; прогноз последней клетки учитывает этот урон.
- **Комнаты замка:** носитель ключа открывает путь через магические двери. Физические удары не снимают печать, но бомба может открыть выбранную дверь. После снятия печати всё равно нужно войти цепочкой.
- **Развилки:** наведение на дверь и её выбор в цепи показывают следующий тип комнаты. Схема отмечает продвижение к башне; назад вернуться нельзя. Среди залов — пиршественный, караульный, шахматный и библиотека.
- **Награда:** после выхода из комнаты выберите один из трёх предметов. Следующая комната соответствует уже выбранной двери. Инвентарь переносится между комнатами похода.
- **Противники:** шкаф защищает одного соседа (у большого шкафа — соседа любой его клетки) от части физического урона; убийство или заморозка шкафа снимают защиту. Ладья, слон и конь используют различимую геометрию. Конкретные намерения всегда показаны до действия игрока.
- **Финал:** сначала разрушьте печать колдуна на 18 HP, затем победите его самого на 24 HP. Снятие печати останавливает текущую цепь.
- **Повтор:** «Повторить комнату» восстанавливает снимок на входе, включая здоровье и предметы. «Поход сначала» начинает заново у ворот. Повтор не выдаёт награду дважды.

Кривая сложности и следующие запланированные ступени описаны в [дизайне начала игры](docs/levels/opening-sequence.md). После тринадцатого боя начинается Тюремщик. Его победа открывает выбор: добраться до выхода или уничтожить колокол подкреплений. Каждая ветка завершается отдельно и предлагает лесное испытание. Доступны 16 авторских полей; один путь проходит через 15 из них.

Основная платформа интерфейса — ПК. Цель, здоровье, энергия и действия находятся рядом с полем; прогноз появляется при выборе цепи. Кнопка «← В редактор» после боя по авторскому уровню стоит в левой панели под «В меню»; на титуле «Создать уровень» и «Как играть» лежат в правой колонке под испытаниями; у ворот поле уменьшается на высоту карточки залпа, чтобы строка статуса помещалась в 1280×720. Метка у конца цепи говорит «В СЛЕДУЮЩИЙ ЗАЛ» только при входе в открытую дверь, при победе — «ПОБЕДНЫЙ УДАР». Подробности боя, правила врагов и обозначения раскрываются по запросу. [Правила настольного UX](docs/desktop-ux.md).

Тюремщик закрывает цепной подход спереди щитом, бьёт по объявленному сектору на 2 HP и затем один ход отдыхает с опущенным щитом. Промах тоже даёт передышку. Колокол сам не атакует: каждый второй активный ход заменяет до двух заранее отмеченных врагов вооружёнными. Цель — живой спокойный одноклеточный обычный враг ближнего боя без варианта (или стул) с 0 HP, без щита и ключа, на проходимой клетке, не под котом и не на устройстве; табуреты и другие варианты не объявляются. Убийство колокола останавливает призыв; обе фигуры доступны в редакторе.

## Поход по карте леса

Поход по нодовой карте леса ([дизайн](docs/biomes/forest-map.md), раздел «Реализовано / временно»): модель, API движка и экран карты. Точка входа — кнопка **«ПОХОД ПО ЛЕСУ»** справа вверху титула. При сохранённом походе она называется «ПРОДОЛЖИТЬ ПОХОД» (или «ИТОГ ПОХОДА», если поход закончен), рядом есть «НАЧАТЬ ЗАНОВО» с подтверждением на самой странице (без `window.confirm`).

**Экран карты** (`src/forestMapScreen.ts`, поверх `forestRunView`) помещается в 1280×720 без прокрутки:
- Ряды графа идут слева направо, три полосы сверху вниз: звериная тропа и логово к Троллю — сверху, общий путь — по центру, гоблинская засека и лагерь к Главарю — снизу. Подписи полос показывают ветки.
- Статусы узла: пройден (галочка), текущий (последний пройденный), доступен (пульсирующая рамка, клик входит в узел), закрыт (приглушён); незавершённый бой узла выделен красным. Иконки типов: бой ⚔, элита ☠, привал ☾, находка ◈, прорыв ⇥, контрольный ▣, босс ♛. Пунктирная рамка — временный бой.
- Наведение или фокус с клавиатуры показывает под картой тип узла, особенность поля, что он открывает, метку «временно».
- Над картой: HP, энергия, предметы и открытые инструменты, число пройденных боёв; справа «В МЕНЮ» и «НОВЫЙ ПОХОД» (с подтверждением).
- Вход в бой открывает прежний экран боя. Кнопок урока («следующий бой», «к воротам», выбор ветки урока) в нём нет, слева вместо «В меню» — «← К КАРТЕ». После победы — «К КАРТЕ»; после поражения — «ПОВТОРИТЬ УЗЕЛ» и «К КАРТЕ» (узел остаётся текущим, число поражений сохраняется). Победа над элитой ведёт к находке; над Тюремщиком открывается круговой удар — экран сообщает об открытии.
- Привал показывает, сколько вылечено; находка — выбор одного из трёх предметов (тот же вид, что награды замка). Итог: победа над любым боссом, Главарём или Троллём, завершает поход окном «ПОХОД ЗАВЕРШЁН» с «НОВЫЙ ПОХОД» и «В МЕНЮ».
- Сохранение происходит после каждого шага модели. После перезагрузки титул предлагает продолжить: поход возвращается на карту, а начатый бой узла — к его началу (бой в процессе не сохраняется).
- Телеметрия различает бои узлов: ключ попытки `run:<id узла>`, режим `run`.
- Проверка: `tests/forest-map.spec.ts` (входит в `npx playwright test`).

- `src/game/run/forestMap.ts` — авторский граф: ствол из 4 боёв, развилка на звериную тропу и гоблинскую засеку с общими привалом и находкой, общий бой «Три знамени», Тюремщик, затем ветки «Логово» (к Троллю) и «Лагерь гоблинов» (к Главарю). На любом пути 12–13 боёв. Узлы троп и обеих веток используют бои реестра `src/game/run/forestBattles.ts`, в том числе арену Тролля `troll-lair`. Ствол, «Три знамени» и Тюремщик остаются на уроках, Главарь — лесное испытание. Временным помечен только `den-elite`: он ждёт Медведя или Зверовода.
- `src/game/run/forestRun.ts` — чистая модель: seed похода, текущий и пройденные узлы, доступные переходы, результат. Между узлами переносятся HP, энергия, предметы и стаки эффектов. Инструменты открывает событие похода, а не урок: холод — первый узел каждой тропы, прыжок — любой узел седьмого ряда, в том числе находка, круговой удар — победа над Тюремщиком. Находка и победа над элитой предлагают выбор из трёх предметов, как награды замка; выбранный предмет становится доступным. Привал лечит на 2 HP до максимума (временный параметр баланса) и снимает горение, яд и кровотечение. Палитра пополнения зависит от ряда карты: 2, 3, 4, затем 5 цветов, плюс цвета стартовой расстановки шаблона. Seed боя выводится из seed похода и id узла.
- `ForestEngine.startRunBattle(setup)` запускает бой узла с ресурсами и разрешениями похода. `runBattleOutcome()` возвращает итог в модель. «Повторить бой» восстанавливает снимок на входе в узел. Поражение не завершает поход: узел повторяется с запасом на входе.
- `src/game/run/forestRunStorage.ts` — сохранение в `localStorage` под ключом `ashen-oath-forest-run-v1`. Без хранилища поход живёт в памяти. После перезагрузки начатый бой узла начинается заново с того же снимка входа.

## Цвета и сложность

Палитра расширяется без возврата к двум цветам: бои 1–8 — красный и синий; 9–11 — добавляется зелёный; 12–13 — охра; 14–16 — аметист. На поздних картах новые цвета собраны в соседние группы для цепей. Стартовая расстановка подготовлена вручную. После убийств цвета новых врагов случайно выбираются из взвешенной палитры боя; цвет не закреплён за координатой. Отдельные совпадения допустимы. Проверка доступного хода может менять только новых, ещё не показанных врагов.

Лесное испытание, ворота и все комнаты замка используют пять цветов. Пополнение воспроизводимо по seed; проверка доступной цепи корректирует только новых врагов, сохраняя цвета выживших. В редакторе по-прежнему действуют заданные автором веса, включая отключённые цвета. [Подробности прогрессии](docs/levels/opening-sequence.md).

## Управление и общие правила

- Начинайте на враге **рядом с котом**. Мышью или пальцем проведите цепь минимум через две соседние цели одного цвета. Для входа в доступную соседнюю дверь достаточно выбрать её одну и отпустить; для боевой цепи минимум две цели сохраняется. Обычная цепь идёт в восьми направлениях, включая диагонали. Диагональ через угол запрещена, если обе соседние клетки по сторонам непроходимы. Обычные ближние враги атакуют только по четырём сторонам; геометрия особых врагов задаётся их собственными правилами.
- Возврат на предыдущую клетку сокращает цепь. Отпускание снаружи поля подтверждает допустимый путь. Одиночное нажатие на врага не тратит ход; Escape отменяет выбор.
- **Устройства:** рычаг в цепи запускает стрелы после её завершения, жаровня даёт по 1 горению всем следующим попаданиям этой цепи. Устройства сохраняют цвет и не добавляют силу. Рычаг провалов открывает выбранные люки после цепи: обычные враги падают, падение кота смертельно. Следующий ход клетки непроходимы, затем закрываются; под боссами, дверями и крупными врагами люк заклинивает. Стрелы опасны и для кота; заряды ограничены. [Правила и JSON](docs/devices.md).
- **Запас силы цепи:** первый враг даёт 1, каждый следующий ещё +1. Слабые гоблины и обычные стулья имеют 0 HP: погибают от попадания и не расходуют запас. Крепкие цели расходуют его на снятые HP. Пять слабых дают 5; следующий враг с 5 HP поднимает запас до 6 и оставляет после убийства 1. Последнюю цель можно ранить, но пройти через живую нельзя. [Полные правила и модификаторы](docs/chain-budget.md). Цвета задают соединение, а не стихию.
- Промежуточный враг обязан погибнуть. Последнего можно ранить; его HP сохраняются. Кот остаётся на последней освобождённой клетке. Бесцветный главарь принимает любую цепочку, но через живого главаря пройти нельзя.
- В походе и в авторских уровнях редактора (не в обучающих боях) цепочка с **8 убийствами врагов** может оставить огонёк на освобождённой клетке; одновременно на поле не более двух огоньков. Он позволяет сменить цвет внутри следующей цепи, не усиливая удар как враг; начать с него нельзя. Награда не создаётся при завершении комнаты или отсутствии подходящей клетки. Предпросмотр сообщает, когда огонёк появится.
- Красный знак **!** и отмеченные клетки показывают уже выбранные атаки врагов. Бирюзовые стрелки **⇄** показывают обмен содержимым двух отмеченных клеток, **…** — отдых без обмена. Текст под полем дублирует число врагов и координаты пары, например G3 ↔ G2. Сводка «Готовы атаковать / Отдыхают» считается правилами движка (`evaluateEnemyAttack`, `planEnemyPhase`): пассивные враги и колокол в «готовые» не попадают. Гибель участника не убирает объявленную пару клеток: перед обменом пустое место займёт обычное пополнение. Если кот закончит цепь на одном из концов, обмен отменяется; живой замороженный участник также останавливает его. Перед отпусканием цепи видны прогноз ответного урона и клетка, где останется кот. Деревья, глубокий пруд и костёр непроходимы.
- **Обычный гоблин атакует только по четырём сторонам**, без диагоналей. Его злость сохраняется, если кот ушёл из замаха. После успешного попадания по коту гоблин пропускает одну фазу действий спокойным. Каждый ход могут появляться новые разозлённые противники: угрозы накапливаются, если их не убирать.
- **Лучник стреляет в заранее выбранную линию**, даже если кот вышел из неё. Выстрел получает каждое существо на объявленных клетках — кот и враги; убийства засчитываются игроку, двери и огоньки не задеваются (шахматные фигуры по-прежнему бьют только кота). После выстрела он отдыхает одну полную фазу действий; в этой фазе может поменяться местами с заранее отмеченным соседним врагом. Обе фигуры сохраняют здоровье и состояния, а намокание обновляется по наличию лужи в новой клетке. Объявляется пара клеток, поэтому гибель одного или обоих врагов не отменяет обмен. Свободные концы сначала заполняются обычными врагами; новые враги не атакуют в эту фазу. Кот на любом конце и живой замороженный участник останавливают обмен. Если замороженный враг погиб, его новая незамороженная замена не блокирует пару. Другая пара в этом ходу не выбирается. Затем он снова готовит выстрел. Шахматные фигуры выбирают партнёра по своей геометрии: ладья по прямой, слон по диагонали, конь буквой Г; для них обмен не обязательно соседний.
- **Кабан, шипы и колючки** (авторские бои и редактор). Кабан объявляет рывок к коту только по вертикали или горизонтали (при равенстве — вертикаль). В начале следующей фазы врагов, до атак, он бьёт первое тело в ряду и толкает ряд: ряд сжимается в пустоты от цепи, а если сжиматься некуда, передний вдавливается — за край с шипами (враг гибнет, кот получает 1 урон и упирает ряд), в открытый провал, на колючки (1 урон). Стены, край без шипов, устройства, двери, огоньки, боссы, крупные фигуры, замороженные и щит, повёрнутый к кабану, упирают ряд; не сдвинувшийся кабан оглушён. Сдвинутые в этой фазе не действуют. Колючки (`thorns`) проходимы и ранят только вдавленного и кота, закончившего на них обычную цепь. Прогноз цепи учитывает всё это. [Полные правила](docs/gdd.md#5-враги).
  - **Волк, дикобраз, шаман** (авторский JSON, уроки и кисти редактора; фигуры нарисованы процедурно, иллюстраций нет). Волк рядом с живым волком вооружён и зол, одинокий пассивен; если соседа убили до атаки, объявленный удар отменяется. Каждое попадание обычной цепи по дикобразу ранит кота на 1 (прогноз показывает `spikeDamage`), смерть от игл — поражение до победы; прыжок, круговой удар, стрелы и рывок иглы не вызывают. Шаман каждый второй ход объявляет до двух соседних гоблинов и после атак поднимает их на ступень: слабый → вооружённый → крепкий (2 HP); смерть или заморозка шамана либо смерть цели отменяют камлание. Лёд выключает иглы, удар волка и камлание. Правила — `src/game/forestBeasts.ts`, [GDD, раздел 5](docs/gdd.md). На экране: линии-связи между волками стаи и метка «ОДИНОК» у пассивного; «−1 ИГЛЫ» на дикобразе при выборе цепи (и «БЕЗ ИГЛ», если он заморожен); у шамана цели камлания помечены рамкой и «↑ ВООРУЖЁН» / «↑ КРЕПКИЙ», а прогноз цепи показывает «СТАЯ РАЗБИТА» у волков, чей удар отменится, и «КАМЛАНИЕ ОТМЕНЕНО». Строка риска и панель цепи берут суммы из `damageBySource` и `chargeBreakdown`. Заготовка редактора «Лесные звери» (`src/editor/beastsDemo.ts`, JSON — `docs/examples/forest-beasts-demo.json`); проверка — `tests/forest-beasts-ui.spec.ts`.
  - **Лесной тролль** (`variant: 'troll'`, бесцветный босс; авторский JSON и кисть редактора «Тролль 2×2», заготовка «Логово тролля» (`docs/examples/troll-den-demo.json`); ядро и экран 30.09.2026, фигура процедурная, иллюстрации нет; телеграф: замах — пунктирный контур зоны, удар — залитая зона «УДАР 2», в прогнозе крестики «ДУБИНА» и «Тролль восстановит N HP»; проверка — `tests/forest-troll-ui.spec.ts`). Тело — одна клетка или квадрат 2×2, в цепи бьётся один раз; кабан его не сдвигает, провалы не действуют, в обменах не участвует. Дубина — цикл из трёх ходов: **замах** объявляет зону 3×2 перед троллем в сторону кота (только по вертикали или горизонтали, при равенстве — вертикаль) и фиксирует её; **удар** в следующей фазе бьёт на 2 всех существ в зоне, включая врагов (убийства засчитываются игроку, двери и огоньки не задеваются; кот ранен, только если стоит в зоне); затем ход **отдыха**. Лёд приостанавливает цикл: замёрзший тролль не замахивается и не бьёт, после оттаивания продолжает с той же зоной. В конце фазы врагов тролль восстанавливает 3 HP (до максимума), если за ход не получил никакого урона и на нём нет горения. Прогноз показывает урон дубины (`damageBySource.troll`), погибших от неё (`enemyPhase.deaths`, причина `club`) и регенерацию (`enemyPhase.regenerated`). Числа — баланс прототипа. Правила — `src/game/troll.ts`, [GDD, раздел 5](docs/gdd.md#5-враги).
  - **Как это видно на поле.** Рывок кабана — янтарный коридор поверх фигур с шевронами по рельсам и тяжёлой стрелкой на дальнем краю; линия лучника — тонкая стрелка со скобками, а враги на ней получают красный значок прицела (стрела заденет и их). Готовый кабан считается в «Готовы атаковать»; оглушённый — звёзды, метка «ОГЛУШЁН», Ⅱ и ×2. Шипы по краю — железная планка с зубцами поверх крайних клеток; колючки — заросли, а под врагом видна кайма из шипов, не закрывающая цвет и знак. Пока цепь строится, поле показывает прогноз движка: шевроны сдвига ряда, пунктирные клетки итоговых позиций, красные крестики с причиной (УДАР, ШИПЫ, КОЛЮЧКИ, ПРОВАЛ, СТРЕЛА) и, если она отличается от конца цепи, отметку «КОТ ЗДЕСЬ». Панель цепи перечисляет, кто погибнет, а строка риска называет источники урона (весь урон рывка — одной суммой «кабан»: движок пока не разбивает его на удар, шипы, колючки и провал). Ход анимируется: замах и рывок, сдвиг ряда, падение на шипы, оглушение, стрела в цель; всё это только показ и не задерживает отмену устаревшего хода.
- Начальная расстановка авторская. Пополнение сначала создаётся как невидимый кандидат: seeded-генератор выбирает новые цвета, затем общий расчёт проверяет обычную цепь без способности. Неудачный кандидат перебирается до показа. Поиск свидетельства цепи допускает любое число огоньков и устройств между двумя врагами и отсекает недостижимые ветки; страховочный лимит — 4000 оценок цепи на вызов (`GENERATION_SEARCH_BUDGET`). На искусственных полях с очень большим числом устройств и огоньков лимит теоретически может дать ложное «нет цепи». Проверка не перекрашивает и не переставляет уже показанных выживших врагов и не переназначает защиту шкафа ради создания хода. Одинаковый seed и действия воспроизводят результат; случайные попытки ограничены, после них проверяются допустимые варианты только новых целей. Подкрепление, закрывающее оставшийся путь, может ждать следующего обновления. Неудачный прыжок в окружение не вызывает автоматического спасения поля. Места под подкрепления заранее не освобождаются.
- **Энергия:** начало похода — 0, максимум — 7. Обычная подтверждённая цепь даёт +0,5 за каждого атакованного врага, включая выжившую последнюю цель. Двери, огоньки и отменённые цепи энергию не дают. Запас переносится между комнатами; повтор комнаты восстанавливает его значение на входе.
- **Отдых:** даёт +0,5 энергии до предела 7, затем проходит обычный ход врагов: атаки, обмены, залпы и другие события поля сохраняются. Отдых не лечит.
- **Способности:** прыжок за 2 энергии выбирает клетку в пределах расстояния 3 и наносит физический удар 4; приземление возможно на пустом проходимом полу или убитом враге. Круговой удар за 3 сразу наносит физический удар 4 всем восьми соседним врагам; кот остаётся на месте. Хрупкость и защита шкафа учитываются в прогнозе; направленный щит стража и Тюремщика способности игнорируют. Прыжок отменяется повторным нажатием, кнопкой отмены или Esc до исполнения. Способность и прицел расходника выбираются по очереди.
- **Расходники:** холод действует на мокрого врага; бомба наносит 6 урона одной цели или снимает печать двери. Огненная склянка накладывает по одному стаку горения на выбранного врага и врагов по четырём сторонам без мгновенного урона; многоклеточный враг получает один стак. Лечение восстанавливает до 3 HP и полностью снимает яд и кровотечение, даже при полном здоровье; горение остаётся. Выберите предмет и цель, затем проведите цепь либо нажмите «Отдых · +0,5 энергии». На одном ходу можно подготовить один предмет.
- **Накопленные эффекты:** горение и яд наносят в конце хода по 1 урону за стак. Горение теряет один стак после каждого второго такого тика, повторное наложение не обнуляет отсчёт; яд сам не слабеет. Кровотечение наносит по 1 урону за стак после каждых трёх обычных шагов кота и теряет один стак в конце хода. Прыжок и обмен врагов шагами не считаются. Ветер добавляет стак горения только уже горящей цели. Эффекты удара в авторском уровне дополняют обычный физический удар и накладываются на выжившую цель; сами они не наносят урон при наложении. HUD и фигуры показывают стаки, а прогноз цепи — ожидаемый урон от кровотечения и периодических эффектов. Убийство отложенным эффектом не считается физическим попаданием или убийством внутри той же цепи. Подробный порядок указан в [правилах эффектов](docs/damage-effects.md).
- Заморозка пропускает ближайшее действие и приостанавливает отсчёт отдыха, не снимая злость. Хрупкость удваивает следующий физический удар. Сухая цель не расходует холод.
- Escape или «Отмена» закрывают прицел флакона. После применения отмены расходника нет. Escape без выбранной цепи открывает паузу. Повтор боя доступен в паузе и на экране результата, без перезагрузки страницы.
- На мобильном экране во время цепочки короткая строка над полем показывает длину, силу последнего удара и входящий урон; поле не сдвигается при выборе.
- Между запусками браузера сохраняются лучший результат, настройка звука и поход по карте леса (`ashen-oath-forest-run-v1`). Поход по замку хранится в памяти открытой страницы.

## Лесное обучение

Сначала победите 8 обычных гоблинов, затем 2 лучников и главаря на 20 HP. Каждый прибывший особый противник раздавливает случайного обычного гоблина; это не приносит игроку очков или прогресса. Герой и другие особые враги не заменяются. Лужа E2 мочит стоящего в ней врага; со второй волны доступен флакон холода. Лимита ходов нет.

## Плейтест

Локальная телеметрия помогает измерять сложность боёв на живых игроках. Данные хранятся только в `localStorage` браузера под ключом `ashen-oath-playtest-v1` (последние 500 попыток) и никуда не отправляются. Правила боя, RNG и порядок событий телеметрия не меняет: она наблюдает события движка и команды игрока. Без хранилища игра работает как прежде.

- **Попытка** — от старта или повтора боя до победы, поражения, повтора или выхода (в меню, редактор, закрытие вкладки).
- **Экран «Плейтест»:** мелкая ссылка «ПЛЕЙТЕСТ» в подвале титула (в бою скрыта) или раскрываемый блок «Плейтест» в паузе. Таблица агрегатов по боям, кнопки «Скачать JSON», «Скопировать JSON», «Очистить» (с подтверждением на странице) и переключатель журнала.
- **Отключение:** `?telemetry=0` выключает журнал и запоминает это в том же ключе; `?telemetry=1` включает снова.
- **Как проводить сессию и какие цифры считать тревожными:** [docs/playtest-protocol.md](docs/playtest-protocol.md).

Формат экспорта (`format: "ashen-oath-playtest"`, `version: 1`):

```json
{ "format": "ashen-oath-playtest", "version": 1, "exportedAt": "ISO-8601", "enabled": true,
  "attempts": [ { "key": "tutorial:0", "mode": "tutorial", "id": "chain", "index": 0, "seed": 101,
    "startedAt": 1790000000000, "durationMs": 21400, "outcome": "win", "left": false,
    "visit": 1, "attemptInVisit": 2, "turns": 3, "hpEnd": 5, "maxHp": 5, "damageTaken": 0,
    "chains": 3, "chainAvg": 2.33, "chainMax": 3, "cancelledChains": 0,
    "abilities": {}, "items": {}, "firstMoveMs": 4200 } ],
  "aggregates": [ { "key": "tutorial:0", "label": "Бой 1 · chain", "attempts": 2, "visits": 1, "wins": 1, "loses": 0,
    "winRate": 0.5, "loseRate": 0, "attemptsToWin": 2, "medianWinMs": 21400, "medianQuitMs": null,
    "medianFirstMoveMs": 3900, "abandonRate": 0, "avgCancelled": 0.5, "avgChainLength": 2.33 } ] }
```

Поля попытки: `key` — ключ боя (`tutorial:<индекс>`, `forest`, `campaign:<тема>:<глубина>`, `custom:<название>`, `run:<id узла>` для боя узла карты леса); `mode`, `id` — режим и идентификатор (для урока — id и индекс, для леса, похода и авторского уровня — название) и `seed`; `outcome` — `win`, `lose`, `restart` или `quit`; `left` — игрок ушёл с этого боя (в том числе сразу после поражения); `visit` и `attemptInVisit` — заход в бой (до победы или ухода) и номер попытки в нём; `turns` — подтверждённые ходы (цепи, способности, отдых); `damageTaken`, `hpEnd`; `chains`, `chainAvg`, `chainMax` — подтверждённые цепи; `cancelledChains` — цепи из двух и более клеток, отброшенные Escape, отменой указателя или невалидным отпусканием (одиночный клик по врагу — осмотр, не считается); `abilities`, `items` — использования по видам; `firstMoveMs` — время до первого хода (чтение поля; включает загрузку графики). Длительность идёт по стенным часам, пауза не вычитается.

Агрегаты по бою: `winRate` и `loseRate` — доли попыток; `attemptsToWin` — медиана числа попыток до первой победы среди заходов, дошедших до победы; `medianWinMs`; `medianQuitMs` — время попыток, закончившихся выходом; `abandonRate` — доля заходов, завершённых уходом без победы.

## Структура

- `src/game/forestEngine.ts`, `forestTypes.ts`, `forestLevel.ts` — состояние, команды игрока, лесное обучение, генерация и управление походом.
- `src/game/components.ts` — структурные компоненты сущностей: здоровье, состояния, поведение, намерения, связи, щит и занимаемые клетки.
- `src/game/turnSystems.ts`, `turnRuntime.ts` — последовательность систем хода и отдельный исполнитель событий и задержек анимаций.
- `src/game/enemyPhase.ts`, `combatRules.ts` — общие правила выбора атакующих, урона, удаления сущностей и зачёта убийств.
- `src/game/damageEffects.ts`, `effectRules.ts` — стаки горения, яда и кровотечения, тики, очищение и применение эффектов удара.
- `src/game/campaignContent.ts` — шаблоны комнат, варианты направлений и описания расходников.
- `src/game/tutorialLevels.ts`, `src/game/lessonBuilder.ts`, `src/game/lessons/*.ts` — 16 авторских полей (бои 1–6, 7–10, 11–16 по файлам) с несколькими цветами, отмеченными целями, постепенным открытием механик и случайным пополнением из палитры боя; построитель `authoredLesson` и формат карты урока.
- `src/game/forestSystems.ts` — последовательный расчёт цепи, общий для предпросмотра и исполнения.
- `src/game/run/` — поход по карте леса: граф узлов (`forestMap.ts`), чистая модель похода (`forestRun.ts`), контракт с движком (`runBattle.ts`), сохранение (`forestRunStorage.ts`), реестр авторских боёв узлов (`forestBattles.ts`, данные в `battles/*.ts`, порядок — [как добавить бой узла](docs/biomes/forest-map.md#как-добавить-бой-узла)) и постановка их анализа (`nodeAnalysis.ts`). Проверка — `test:forest-run`.
- `src/forestMapScreen.ts` — экран карты леса: HTML карты, ресурсов, подсказок узла, титульной кнопки, привала, находки и итогов; склейку с движком и сохранением делает `src/main.ts`. Проверка: `tests/forest-map.spec.ts`.
- `src/game/forest.spec.ts`, `campaign.spec.ts` — проверки лесных правил и похода.
- `src/render/` — PNG-персонажи, процедурное окружение и запасная отрисовка, указатели опасности, ввод и анимации PixiJS.
- `src/main.ts`, `src/style.css`, `src/audio.ts` — русские экраны, HUD, расходник и синтезированный звук.
- `src/telemetry.ts` — локальная плейтест-телеметрия: журнал попыток, агрегаты по боям, экран «Плейтест». Проверка: `tests/telemetry.spec.ts`.
- `docs/castle-campaign.md` — решения по кампании и статус проверки; `docs/design-references.md` — первичные источники дизайнерских ориентиров.

Порядок систем, границы расчёта и правила добавления механик описаны в [архитектуре игрового ядра](docs/architecture.md). Текущая модель использует структурные компоненты и явные системы хода; отдельного ECS-реестра или внешней ECS-библиотеки нет.

## Анализатор уровней

`npm run analyze:levels` оценивает 16 боёв начала пути и лесное испытание; `-- --lesson N`, `-- --json level.json` (формат редактора), `-- --node ID` и `-- --nodes` (бои узлов карты леса, как в походе), `--seeds`, `--depth`, `--out report.json` и другие флаги описаны в [метриках уровней](docs/level-metrics.md). Анализ работает на отдельных экземплярах движка через снимок позиции (`captureAnalysisSnapshot`/`restoreAnalysisSnapshot`), исполняет действия обычными командами и не меняет правила, живую игру и её RNG.

Считаются: статика стартового поля (компоненты одного цвета, переплетение цветов, доля безопасных первых цепей, клетки под атакой); поиск-оракул по дереву ходов с настоящим seed (минимум ходов, HP, число решений, доля выигрывающих и проигрышных первых ходов, узкие места wₜ/KM); честный планировщик без знания пополнения и разрыв удачи FG; решатели без способностей, предметов, устройств или огоньков (необходимость механики); случайный и жадный агенты с информацией −log₂ P в битах и интервалом Уилсона; обманчивость для жадного агента и разброс по seed. Все значения — эвристические оценки с флагами полноты, а не доказательства. `npm run test:level-analysis` проверяет сам анализатор на искусственных полях.

## Проект первых уровней

[Первая глава](docs/levels/opening-sequence.md) — 16 авторских боёв, построенных по [руководству по дизайну боёв](docs/level-design-guide.md). Кривая идёт «пилой»: каждый блок механики проходит путь «урок → применение или поворот → экзамен», после пика следует спад.

- **Бои 1–3** ([карты](docs/levels/tutorials.md)): цепь с диагоналями, запас силы, первый экзамен на место остановки.
- **Бои 4–6** ([карты](docs/levels/forest-trail.md)): рычаг стрел, жаровня, экзамен на сочетание устройств.
- **Бои 7–10** ([карты](docs/levels/advanced-trail.md)): холод, прыжок, огонёк с третьим цветом, экзамен со стрелком.
- **Бои 11–13** ([карты](docs/levels/pit-trail.md)): временные провалы, поворот, экзамен.
- **Бои 14–16** ([карты](docs/levels/chapter-finale.md)): Тюремщик со щитом и окном отдыха, затем выбор между выходом через ворота и гонкой с колоколом подкреплений.

Соседние бои не повторяют каркас: меняются форма поля, стартовая клетка кота и направление движения. С третьего боя появляются вооружённые рядовые. На экзаменах 3, 10, 13, 14 и 16 рефлекс «самая длинная цепь» больше не выигрывает надёжно: по анализатору жадный агент проигрывает там от трети до двух третей прогонов. Метрики анализатора «до/после» приведены в документах блоков; сложность на людях ещё не измерялась. Любой бой можно выбрать на титуле и точно повторить.

## Редактор уровней

На главном экране нажмите **«Создать уровень»**. Выберите одну из трёх исходных заготовок или нарисуйте собственную карту размером от 4×4 до 12×12. Кисти размещают местность, кота, выходы и противников с выбранными цветом, HP, готовностью к атаке и необязательным эффектом удара. Для кота эффект удара задаётся отдельно. Доступны огонь, яд, кровотечение и ветер; эффект добавляется к физическому попаданию. В JSON это необязательные поля `playerAttackEffect` и `enemies[].attackEffect`; прежние уровни без них работают. Неизвестные значения отклоняются при импорте: поля-перечисления (`kind`, `variant`, ключ цели, тип устройства, местность) должны быть строками, а страж со щитом (`sentinel`) — одноклеточным. Гардероб занимает четыре клетки 2×2; изменение любой его части непроходимой местностью удаляет сущность целиком. Кисти проходимой местности — пол, лужа и колючки — сохраняют стоящего на них врага, а кисть врага сохраняет под ним лужу или колючки; стена, дерево, вода и костёр убирают врага. Устройства и выходы по-прежнему ставятся на пол. «Автозаполнение» убирает нарисованного противника и возвращает пол, чтобы на игре здесь появился случайный. Рычаг стрел и жаровню можно нарисовать отдельными кистями; для рычага задаются линия и заряды. Среди противников есть кабан (по умолчанию 3 HP; «Готов к атаке» на него не влияет), среди местности — колючки; флажки «Шипы» задают стороны поля с шипами (`spikedEdges` в JSON) и обводятся красной каймой на сетке. Заготовка «Кабан, шипы и колючки» в списке заготовок (и файл `docs/examples/boar-thorns-demo.json`, который можно импортировать) — готовое поле для ручной проверки: кабан над колонной гоблинов, лучник сбоку, шипы снизу, колючки внутри. Виды «Волк» (по умолчанию 0 HP), «Дикобраз» и «Шаман» (по 2 HP) выбираются в списке «Вид»; «Тролль 2×2» (по умолчанию 24 HP, бесцветный) ставится, как гардероб, на четыре клетки, в JSON допустима и одна клетка; заготовка «Логово тролля» (`docs/examples/troll-den-demo.json`) — тролль 2×2 над гоблинами; заготовка «Лесные звери» (`docs/examples/forest-beasts-demo.json`) — стая из трёх волков и одинокий волк, дикобраз у первых шагов, шаман среди слабых гоблинов. Доступны отмена/возврат до 50 изменений. Поля совпадают с ограничениями валидатора: название до 100 символов, seed 0…4294967295, лимит ходов до 1000, цели до 10000, задержка цвета до 1000. Введённое значение применяется до рисования, фокус клавиатуры сохраняется после изменений, Enter на клетке рисует. Сетка ограничена высотой окна, чтобы «Играть» оставалась на первом экране. В авторских уровнях действует награда-огонёк за 8 убийств одной цепью (те же правила, что в походе: не более двух огоньков, не при завершении боя); отключить её в редакторе нельзя.

Задайте одну или несколько целей: убийства, стрелки, главари или выживание. Для целей по особым врагам разместите достаточно нужных противников: пользовательский уровень не получает скрытых лесных подкреплений. После целей можно сразу выиграть либо открыть выход и дойти до него цепью. Лимит ходов, seed, здоровье и стартовые предметы настраиваются справа; повтор восстанавливает начальные данные.

Палитра содержит пять цветов со знаками **▲ ✚ □ ● ✕**. Веса относительные: `100 / 100 / 20 / 0 / 0` делает третий цвет редким, а последние два исключает из автоматического заполнения. Это не проценты и не перекраска уже показанных врагов. Нарисованные вручную цвета сохраняются даже при нулевом весе. Дополнительный цвет должен иметь нулевой начальный вес; его новый вес вступает через заданное число завершённых ходов **после цели** и влияет на новое пополнение. Проверка доступной цепи может корректировать частоты новых кандидатов. Если уровень побеждается сразу после цели, поздняя палитра уже не успеет повлиять на бой — для неё выбирайте выход.

**«Играть»** запускает тот же движок, что готовые уровни. Кнопка **«← В редактор»** (левая панель, под «В меню») возвращает неизменённый черновик; во время разрешения хода она заблокирована. Сохранение по названию и автосохранение черновика используют локальное хранилище браузера. Сохранений не более 50: новое имя сверх предела не сохраняется, появляется сообщение, а перезапись существующего имени разрешена; уже накопленные сверх предела записи остаются в списке. JSON можно показать, скачать или импортировать из текста/файла. Импорт проверяется до замены карты; ошибочный JSON не стирает текущий черновик. Повреждённый сохранённый черновик не ломает приложение: открывается заготовка, а прежний JSON остаётся для исправления. При очистке данных браузера локальные сохранения исчезают — используйте скачанный JSON для переноса и резервной копии.

Файлы: `src/editor/LevelEditor.ts` — интерфейс; `src/editor/boarDemo.ts` — заготовка с кабаном; `src/game/customLevel.ts` — общий формат и валидация; `tests/editor.spec.ts` — реальное рисование, хранение, импорт, игра и мобильный ввод. Проверка схемы/runtime: `npm run test:custom`.

## Отладка

`window.__PUZZLE_GAME` существует только на dev-сервере (`npm run dev`) или в сборке с `VITE_E2E_HOOKS=1`; в обычной production-сборке (`npm run build`) его нет. Он предоставляет `state`, `phase`, `wave`, `player`, `board`, `turn`, `objective`, `score`, `selectedPath`, `engine`, а также:

- `currentLevel` (индекс уровня `state.levelIndex`), `screen` (имя открытого экрана интерфейса), `frostTargeting` (идёт ли выбор цели холода), `itemTargeting` (выбираемый предмет или `null`), `endpointLabel` (метка у конца цепи: `visible`, `text`, `textWidth`, `plateWidth`), `rendererTicking` (идёт ли отрисовка Pixi: на титуле и в редакторе она остановлена);
- `availableMoves()`, `validStarts()`, `preview(path)`, `previewRotations(path)`, `getBoardState()`;
- `energy`, `chosenAbility`, `setAbility(kind)`, `previewAbility(kind, index)`, `useAbility(kind, index)` — `kind`: `jump`, `spin`; `setAbility(null)` отменяет выбор;
- `beginChain(index)`, `extendChain(index)`, `releaseChain()`, `cancelChain()`;
- `loadTutorial(index)` — авторский бой 0–15; `nextTutorial()` — линейный переход после победы; на развилке нужен выбор кнопкой;
- `previewFrost(index)`, `useFrost(index)`, `previewItem(item, index)`, `useItem(item, index)`, `endTurn()`; `waitTurn()` — то же, что `endTurn()` (отдых), `prepareFrost(index)` — то же, что `useFrost(index)`;
- `startCampaign(seed)`, `startCastle(seed)`, `continueCampaign()`, `chooseReward(item)`;
- `restartLevel()`, `restartRun()`, `loadLevel(index)` (0 — лес, 1 — ворота, 2 — первый внутренний зал), `loadScenario('forest' | 'gate' | 'banquet' | 'barracks' | 'chess' | 'library' | 'wizard', seed)`; прежний псевдоним `castle` открывает `banquet`;
- `room`, `run`, `seed`, `doors`, `rotations`, `key`, `hazard`, `inventory`, `rewards`, `damagePlayer(amount)`, `winLevel()`;
- `gridToScreen(x, y)` или `gridToScreen(index)` для браузерных тестов.

`animationScale = 0` ускоряет проверки; обычное значение — `1`.
