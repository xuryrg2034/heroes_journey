# Делегирование в Codex

Codex CLI установлен (`/opt/homebrew/bin/codex`), авторизован, по умолчанию использует `gpt-6-astra`. Codex сам читает `AGENTS.md` проекта, так что правила проекта ему известны. Задачу нужно описать самодостаточно: истории этой сессии у него нет.

## Когда использовать

- **Арт** — только через Codex: у Claude Code нет генерации изображений. Подробный порядок — в скилле `character-art`.
- **Второе мнение:** `codex exec review` или вопрос по конкретному diff/файлу. Полезно для трудно проверяемых изменений правил боя.
- **Альтернативная реализация** или исследование в отдельной копии, когда нужно сравнить подходы.
- **Не использовать** для задач, которые быстрее сделать самому или помощником Claude, и не отдавать Codex приёмку. Приёмку делает основная сессия.

## Вызов

```bash
S="<scratchpad>"   # папка scratchpad текущей сессии Claude
codex exec \
  -C /Users/xuryrg2034/Projects/Godot/grind_test \
  -s <read-only|workspace-write> \
  -c model_reasoning_effort='"<low|medium|high>"' \
  -o "$S/codex-<задача>.md" \
  "<самодостаточный промпт>" </dev/null > "$S/codex-<задача>.log" 2>&1
```

- `</dev/null` обязателен, иначе `codex exec` ждёт stdin.
- Итоговый ответ Codex — в файле `-o`. Лог служебный. Строки `ERROR ... responses_websocket ... Proxy URL scheme not supported` — шум: Codex переходит на HTTP.
- Работа занимает от минут до десятков минут: запускать с `run_in_background: true` и продолжать свою работу.
- **Sandbox:**
  - `read-only` — ревью и вопросы;
  - `workspace-write` — изменения файлов и генерация арта.

  `danger-full-access` и `--dangerously-bypass-approvals-and-sandbox` не использовать без явного разрешения пользователя.
- **Effort:** `low` — простые вопросы, `medium` — арт и небольшие правки, `high` — архитектура и сложные правила. `xhigh` — только для особо трудных задач.
- Ревью: `codex exec review` с тем же `-C`. Для незакоммиченных изменений описать область в промпте.

## Промпт для Codex

Включить:

1. Цель и наблюдаемый критерий готовности.
2. Точную область файлов: что можно менять и что нельзя.
3. Ограничения из `AGENTS.md`, относящиеся к задаче. Особенно раздел «Границы требований»: не расширять требование на другие режимы, не менять правила ради маршрута или теста.
4. Требуемые проверки.
5. Формат отчёта: что изменено, какие файлы, какие проверки реально выполнены и с каким результатом, риски.

## После возврата

- Прочитать отчёт и **проверить diff самостоятельно** (`git diff`, `git status`): отчёт Codex не является приёмкой.
- Прогнать `verify-all`, а если затронуты правила — `determinism-check`.
- Не принимать изменения вне согласованной области. При необходимости откатить (`git checkout -- <файл>`) и поставить задачу заново.
- Если Codex и Claude-помощник работают одновременно, их области файлов не должны пересекаться.
