# Добавление механики: $ARGUMENTS

Прочитать перед началом: `AGENTS.md` (раздел «Детерминизм — условие приёмки»), `docs/realtime-prototype.md` (правила цепи) и профильный документ: `docs/realtime-slice.md` (враги, способности, предметы), `docs/realtime-phase-a.md` (скорости, составы, аффиксы), `docs/realtime-phase-b.md` (сборка), `docs/realtime-damage.md` (урон и броня элит).

## 0. Уточнить границы

- Где действует механика: песочница, поход, один ряд, одна арена. Решение для песочницы не означает решение для похода. Правила похода включают `RT_RUN_FORCED` (`run/rtRun.ts`) и `RUN_FORCED` (`sim/params.ts`).
- Критерии приёмки — наблюдаемый игроком результат, а не таблица реализации.
- Если трактовка неоднозначна и от неё зависит правило, спросить пользователя. Новый пункт HUD — только по решению дизайна.

## 1. Карта изменений

| Слой | Файл | Что проверить |
|---|---|---|
| Параметр правила | `sim/params.ts` | Поле в `Params`, значение в `DEFAULT_PARAMS`, запись в `PARAM_DEFS` (панель отладки). Код читает ключ так, чтобы отсутствие ключа (`undefined`) давало прежний путь: образец `wolfRing` (`if (!p.wolfRing)` — прежнее поведение). Правило похода — в `RUN_FORCED` или `RT_RUN_FORCED` |
| Поля мира | `sim/world.ts`, `sim/hash.ts` | Новое поле отсутствует, пока не используется. В `worldState` — `...world.field ? { field: world.field } : {}`. Мир без правила хэшируется как раньше. Событийный буфер в хэш не входит |
| Случайность | `sim/rng.ts` | Только именованный поток `world.rng.stream('имя')`. Новый поток не сдвигает старые. `Math.random` нельзя. Трансцендентные `Math.*` (`hypot`, `sin`, `cos`, `atan2`…) нельзя: `sim/detMath.ts` (`dhypot`, `dsin`, `dcos`, `datan2`…) |
| Цепь, проход | `sim/chain.ts`, `sim/buildHits.ts` | `planChain` (подсветка итога) и проход используют одни функции удара. Предпросмотр не меняет мир и не тратит RNG |
| Вид врага | `sim/enemies/*.ts`, `enemies/index.ts` | `registerEnemyKind` и `registerBehavior`; скорость по классу (`speedClasses`); крючки `canBeLinkedFrom`, `damageEnemy`, `killEnemy` с причиной `KillCause` (зачёт игроку: `credited`) |
| Элиты | `sim/elites.ts`, `sim/eliteBehaviors.ts` | Аффиксы, броня, добыча; RNG добычи — поток `loot` |
| Способности, предметы | `sim/abilities.ts`, `sim/items.ts`, `sim/kit.ts` | Расход энергии, `Loadout` арены, команды журнала |
| Сборка | `sim/buildIds.ts`, `sim/build.ts`, `sim/buildModules.ts`, `sim/talismansRt.ts`, `sim/hammers.ts`, `sim/relics.ts` | Id в одном месте; чистые крючки (`modify.*`, `linkPower`) вызываются и в подсветке, и в проходе; изменяющие мир — только в проходе; сигнал `talismanFired` |
| Команды | `sim/commands.ts` | Всё, что меняет мир снаружи симуляции, — команда в JSON; журнал хранит её с тактом |
| Поход | `run/rtRun.ts`, `run/rtTalismans.ts`, `run/rtRunStorage.ts` | `rtArenaLoadout`, предложения, версия сохранения (`RT_RUN_VERSION`, ключ `-vN`): при изменении формата или бросков поход прежней версии читается как «похода нет» |
| Вид | `view/render.ts`, `view/main.ts`, `view/buildColumn.ts` | Реагирует на события и снимок мира, на результат боя не влияет. Не перегружать экран: новое в HUD — только по решению дизайна |
| Логи | `telemetry/observe.ts`, `telemetry/schema.ts` | Поля сводки только добавляются, версия схемы не растёт (`withSummaryDefaults`) |

## 2. Тесты

- Набор `src/realtime/sim/<механика>.spec.ts` (Node, `tsx`), скрипт `test:realtime-<механика>` в `package.json`. Игра идёт командами журнала: `begin`, `drag`, `release`, `place`, `teleport`, `item`, `spin`, `jump`; образцы — `behavior.spec.ts`, `eliteArmor.spec.ts`, `talismansRt.spec.ts`.
- Покрыть:
  - правило срабатывает на своём условии и не раньше; без него поведение прежнее;
  - **подсветка цепи (`planChain`) равна проходу**: итог по каждому звену совпадает с тем, что сделал проход;
  - бой с механикой записан и повторён из журнала до того же хэша (`replay`), хэши каждые 300 тактов;
  - журнал без нового ключа играет прежний мир: `delete journal.params.newKey`, мир без `params` тот же (скрипт: `determinism.ts --keys newKey`);
  - несколько seed (`Math.imul(k, 2654435761) >>> 0`), разнообразие исходов и воспроизводимость;
  - зачёт убийств: способности врагов игроку не засчитываются, инструменты игрока засчитываются.
- Изменение вида или ввода — сценарий Playwright в `tests/realtime-*.spec.ts` (подходящее имя уже попадает в `testMatch` конфига `playwright.realtime.config.ts`). В разработке прогон файла один раз; ×3 — в полном тестировании по просьбе пользователя (`AGENTS.md`). Короткое окно сигнала и ожидание игрового времени читать в странице каждый кадр с пределом в игровых секундах (`untilFrame`, `gameWait` из `tests/realtimeFrames.ts`), а не опросом по настенным часам; «замороженной» сцене ставить и `maxEnemies` 0 (`docs/realtime-slice.md`, раздел 13).
- Если изменение должно менять хэши старых журналов, это решение пользователя. Иначе фикстуры в `tests/fixtures/` должны повториться как раньше.

## 3. Документация (в той же задаче)

- `README.md`, если изменились управление или список проверок.
- Профильный документ из списка выше: что реализовано, какие числа, какой параметр, значение по умолчанию. Плановое и историческое отделять от реализованного. Результаты проверок датировать.
- `docs/realtime-telemetry.md`, если изменились записи логов.
- Удалить устаревшие утверждения. Скилл `docs-sync`.

## 4. Приёмка

Скиллы `verify-all` (с `--browser`, если затронут вид), `determinism-check` (с `--keys <новые ключи>`), затем `docs-sync`. Сверить результат с исходной формулировкой запроса, а не только с зелёными тестами.
