# Синхронизация документации

Постоянное требование пользователя: документация текущего поведения соответствует коду, обновляется в той же задаче.

## 1. Автоматический поиск битых ссылок

```bash
.claude/skills/docs-sync/scripts/doc-refs.sh
```

Скрипт находит:

- **пути** к несуществующим файлам в `src/`, `docs/`, `tests/`, `public/`, `artifacts/`. Скриншоты `artifacts/*.png` помечаются отдельно: их пересоздаёт `npm test`, и в git их нет;
- **неизвестные** `npm run ...`;
- **идентификаторы** в обратных кавычках, которых нет в коде. Проверять вручную. Пути и команды удалённой пошаговой игры в датированных исторических записях законно остаются: они помечены тегом `turn-based-final`. В текущем описании таких ссылок быть не должно.

Относительные ссылки между документами проверяет второй скрипт:

```bash
node .claude/skills/docs-sync/scripts/md-links.mjs
```

Он печатает каждую ссылку в `README.md`, `TRANSFER-RU.md`, `AGENTS.md` и `docs/**/*.md` на несуществующий файл. Якоря (`#раздел`) не проверяются.

## 3. Правила текста

- Явно отделять реализованное от планов и исторических решений. Планы помечать как планы.
- Удалять устаревшие утверждения, а не дописывать «теперь иначе» рядом.
- Результаты проверок: дата, к какому изменению относятся, только реально выполненные. Старые результаты не выдавать за текущие.
- Язык документов — русский. Идентификаторы кода — как в коде.
- `AGENTS.md` — краткая память проекта; подробности уходят в `docs/`, в `AGENTS.md` остаётся ссылка.
