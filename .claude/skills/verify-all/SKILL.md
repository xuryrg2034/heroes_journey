# Полная проверка проекта

Запуск:

```bash
.claude/skills/verify-all/scripts/verify.sh $ARGUMENTS
```

- Без аргументов: `tsc --noEmit`, все `npm run test:*` из `package.json` (список берётся из файла, не хардкодится; это Node-наборы `test:realtime-*`) и `npm run build`. Около 1–2 минут.
- `--only <подстрока>` — typecheck и только совпавшие наборы, без сборки. Для быстрой итерации, не для приёмки.
- `--browser` — дополнительно `npx playwright test`. Конфиг по умолчанию (`playwright.config.ts`) равен набору реального времени (`playwright.realtime.config.ts`): песочница, враги, поход, расходники и талисманы, арены, местность, поведение, камера, петля, элиты, запись логов (`tests/realtime*.spec.ts`), 1 worker; сервер Vite поднимается сам. Если Chromium не установлен, ошибка будет про отсутствующий браузер: выполнить `npx playwright install chromium` и повторить. Это не падение игровых сценариев.

Скрипт печатает `PASS/FAIL` на каждый шаг, для упавших — хвост лога и путь к полному логу.

## Когда нужен `--browser`

Обязательно, если затронуты `src/realtime/view/`, `src/realtime/art/`, `index.html`, ввод, HUD, запись логов в браузере или то, что Playwright проверяет в `tests/`. Для чисто логических правок в `src/realtime/sim/`, `run/`, `forest/` достаточно запуска без флага. Часть тестов браузера нестабильна под нагрузкой: перед приёмкой прогон повторяют ×3 (`npx playwright test --repeat-each 3`) в чистой копии (`AGENTS.md`).

Playwright-тесты перезаписывают скриншоты в `artifacts/*.png`. Они в `.gitignore`; изменения в них не считаются изменениями проекта. Журналы-фикстуры `tests/fixtures/realtime-browser-journal*.json` перезаписываются только при `RT_RECORD_JOURNAL=1`.

## Отчёт

- Сообщать только реально выполненные шаги и их результат. Пропущенный шаг (например, браузерные тесты) называть пропущенным.
- При записи результата в документацию ставить дату и указывать, к какому изменению он относится (требование `AGENTS.md`). Не выдавать старые результаты за проверку текущих изменений.
- Зелёные тесты — необходимое, но не достаточное условие приёмки: отдельно сверить поведение с исходным запросом пользователя (см. раздел «Границы требований» в `AGENTS.md`).
- При падении сначала прочитать лог и понять причину. Не править тест под новое поведение, пока не подтверждено, что новое поведение и есть требуемое.
