# Полная проверка проекта

Запуск:

```bash
.claude/skills/verify-all/scripts/verify.sh $ARGUMENTS
```

- Без аргументов: `tsc --noEmit`, все `npm run test:*` из `package.json` (список берётся из файла, не хардкодится) и `npm run build`. Около 1–2 минут.
- `--only <подстрока>` — typecheck и только совпавшие наборы, без сборки. Для быстрой итерации, не для приёмки.
- `--browser` — дополнительно `npx playwright test` (около 5 минут, 1 worker, порт 4173). Если Chromium не установлен, ошибка будет про отсутствующий браузер: выполнить `npx playwright install chromium` и повторить. Это не падение игровых сценариев.

Скрипт печатает `PASS/FAIL` на каждый шаг, для упавших — хвост лога и путь к полному логу.

## Когда нужен `--browser`

Обязательно, если затронуты `src/main.ts`, `src/render/`, `src/editor/`, `src/style.css`, `index.html`, формат JSON уровней или то, что Playwright проверяет в `tests/`. Для чисто логических правок в `src/game/` достаточно запуска без флага.

Playwright-тесты перезаписывают скриншоты в `artifacts/*.png`. Они в `.gitignore`; изменения в них не считаются изменениями проекта.

## Отчёт

- Сообщать только реально выполненные шаги и их результат. Пропущенный шаг (например, браузерные тесты) называть пропущенным.
- При записи результата в документацию ставить дату и указывать, к какому изменению он относится (требование `AGENTS.md`). Не выдавать старые результаты за проверку текущих изменений.
- Зелёные тесты — необходимое, но не достаточное условие приёмки: отдельно сверить поведение с исходным запросом пользователя (см. раздел «Границы требований» в `AGENTS.md`).
- При падении сначала прочитать лог и понять причину. Не править тест под новое поведение, пока не подтверждено, что новое поведение и есть требуемое.
