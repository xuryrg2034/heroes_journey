# Детерминизм симуляции реального времени

Условие приёмки (`AGENTS.md`): одинаковые seed и журнал дают тот же хэш мира в Node и в браузере.

## 1. Быстрый прогон

```bash
npx tsx .claude/skills/determinism-check/scripts/determinism.ts $ARGUMENTS
```

По умолчанию около 15 секунд. Скрипт выполняет четыре проверки и печатает `ok` или `FAIL` на каждую:

1. **Журналы-фикстуры.** Все `tests/fixtures/realtime-*.json` (записи из браузера, старые журналы сборки) повторяются до хэша, который в них записан.
2. **Свежие бои.** Бот (шаги, цепи через `planChain`, круговой удар, прыжок, предметы) играет 12 арен похода (`RUN_ARENAS`) на seed `Math.imul(k, 2654435761) >>> 0`, `k` = 1…3, с параметрами похода (`rtRunParams`) и снаряжением (расходники, энергия, элиты, талисманы). Журнал записывается, проходит через JSON и повторяется. Хэш в конце и хэши каждые 300 тактов должны совпасть. Тот же seed даёт тот же бой, разные seed дают разные.
3. **Журнал без новых ключей.** Из `params` журнала убираются ключи правил, которые выключены, и повтор должен дать тот же мир: `worldState` без `params` (параметры входят в хэш, поэтому сравнивается всё остальное). По умолчанию убираются все логические параметры со значением `false`. `--keys a,b` проверяет только названные ключи: бои играются с выключенными логическими ключами, затем ключи убираются из журнала. У числового ключа нет «выключено» по умолчанию: его значение для игры задаётся так — `--keys colorShiftLinks=0,focusGuardLinks=0` (с 12.10.2026; без `=` числовой ключ играется со значением параметров похода и снятие ключа меняет мир).
4. **Логи.** `npm run test:realtime-report`: журналы из `tests/fixtures/realtime-logs` повторяются по хэшу (пропуск: `--skip-report`).

Порядок для новой механики: добавили параметр `newRule` — запустить `--keys newRule`. `FAIL` на третьей проверке значит, что код при отсутствии ключа идёт не прежним путём (например, читает `params.newRule` без учёта `undefined`) или новое поле мира попадает в хэш, пока правило выключено.

Скрипт не заменяет профильные наборы. Он проверяет сквозную воспроизводимость на ботах. Правила и крайние случаи проверяют `src/realtime/sim/*.spec.ts`.

## 3. Инварианты, которые нельзя ослаблять

- В `sim/` нет `Math.random` и трансцендентных `Math.*` (`hypot`, `sin`, `cos`, `atan2`…): только `detMath.ts`. Случайность — именованные потоки `world.rng.stream(name)`; новый поток не сдвигает старые.
- Каждое новое правило — параметр `Params` (в `DEFAULT_PARAMS`, `PARAM_DEFS`, при необходимости в `RUN_FORCED`). Он хэшируется. Журнал без ключа играет прежний путь (образец `wolfRing`).
- Новые поля мира отсутствуют, пока не используются (`hash.ts`: `...world.field ? { field } : {}`). Старые миры хэшируются как раньше.
- Подсветка цепи (`planChain`) — это то же, что сделает проход. Расхождение подсветки и прохода — дефект.
- Событийный буфер и время сборки поля потока в хэш не входят.
- Запись логов не меняет хэш боя.
- Журналы из браузера в `tests/fixtures/` не перезаписывают, пока не доказано, что хэш изменился намеренно. Перезапись: `RT_RECORD_JOURNAL=1 npx playwright test -g journal`.

## 4. Новая регрессионная проверка

Если найдено нарушение, добавить тест, который ловит проблему через реальные действия (команды журнала в Node, как в `src/realtime/sim/behavior.spec.ts`), а не повторяет таблицу или алгоритм реализации. Скрипт регистрируется в `package.json` как `test:realtime-<имя>` и упоминается в README (раздел «Проверки»).
