# Арена: $ARGUMENTS

Прочитать перед правкой:
- `docs/realtime-slice.md`, раздел 5 (таблица арен 1–10, «трудные узлы», финал) и шаги 2 и 4;
- `docs/realtime-stage3.md` (местность, поведение, камера, большие арены; принцип «одна особенность — одна арена»);
- `docs/realtime-phase-a.md`, раздел 4 (составы), раздел 6 (большие арены);
- `docs/roguelike-runs.md`, раздел 5 (как поход выбирает арену).

## Порядок

1. **Карточка арены:** одна главная особенность местности, цель (`kills`, `buttons`, `marked`; финал — арена «Последний рубеж»), роль врагов, главное решение игрока, какой ряд похода и что арена должна провалить (например, цепь без обхода щита).
2. **Шаблон** `ArenaTemplate` (`sim/arenas.ts`; `sim/arenasStage3.ts` — арены поведения; `sim/arenasCamera.ts` — большие):
   - размеры (`width`, `height`), `heroStart`, `obstacles` (`wall`, `tree`, `pond`, … ), `buttons`, `door`, `enemies` (стартовые, отмеченные стоят на постах), `goal`, `pace`/`phases`, `newcomers` (доли видов), `braziers`;
   - арена регистрируется `registerArena`, id один раз;
   - добавить шаблон в список (`SLICE_ARENAS`, `TERRAIN_ARENAS`, `BEHAVIOR_ARENAS` или `CAMERA_ARENAS`): оттуда его берут песочница (`view/main.ts`, меню `SANDBOX_ARENAS`) и замеры `scripts/*.ts`.
3. **Пул похода** (`run/arenaPools.ts`):
   - запись `{ arena, rows: [первый, последний] }` в `ARENA_POOLS` — **в конец списка**, чтобы порядок прежних кандидатов не менялся; ряды — ряды похода (ряд карты − 4, 1…9);
   - название — `ARENA_TITLES`; новый id попадает в `RUN_ARENAS`;
   - новый враг учится на своей арене (`OWN_ARENAS`, `NEW_KINDS`, правило первой встречи): проверить `ordinaryArenaChoices`;
   - арена в пуле меняет выбор арен при тех же seed. Поход прежнего формата читается как «похода нет»: поднять `RT_RUN_VERSION` в `run/rtRun.ts` и ключ в `run/rtRunStorage.ts` (как сделали для «Рысьего логова» и «Круга шамана», ключ `-v4`). Это решение — согласовать с оркестратором.
4. **Составы** (`sim/rosters.ts`): арена пула получает состав по броску узла (`pickRoster`, соль `ROSTER_SALT`, поток похода не тратится); арена-якорь — свой враг плюс роль (`ANCHOR_ARENAS`). Новая арена — запись в `POOL_ROSTER_ARENAS` или `ANCHOR_ARENAS`, если ей нужен состав; иначе она играет состав шаблона.
5. **Замеры** (эвристика, записывать в документы с датой, победу бота в тестах не утверждать):
   - `npm run realtime:pockets` — карманов (недоступных мест) 0 на всех аренах, время подхода;
   - `npm run realtime:big-arenas` — бот на больших аренах;
   - `npm run realtime:measure-loops` — петля «Печать» (только песочница);
   - добавленные арены учитывать в списках замеров.
6. **Проверка в игре:** `npm run dev`, `/?sandbox=1&arena=N` или поход `/?seed=N`, при 1280×720: поле, цель, HP, энергия видны на первом экране; метки угроз читаются; на арене можно пройти все цели ходьбой и цепью.

## Правила

- Не менять правила боя ради арены или маршрута. Если арена невозможна без смены правил, остановиться и описать в отчёте.
- Сила арены растёт по ряду похода числом и разнообразием видов, а не только числом HP. Палитра по ряду (`rtColorsByRow`) включается параметром `colorsByRow` и не обязательна.
- Тяжёлые арены (большие, `isBigArena`) масштабируют плотность по площади (`areaScale`, `enemyLimit`): проверить `test:realtime-big-arenas`.
- Стартовая расстановка разнообразна: не заливать арену одним цветом.
- Вид и HUD не меняются. Новое в HUD — по решению дизайна.

## Тесты и документы

- Наборы: `test:realtime-arenas` (шаблоны и цели), `-terrain`, `-slice-terrain` (местность), `-rosters` (составы), `-big-arenas`, `-run` (пулы и поход), `-enemies`. Ожидания менять только там, где изменилось намеренное поведение.
- Playwright: `tests/realtime-arenas.spec.ts` (арены 8–10), `realtime-terrain.spec.ts`, `realtime-behavior.spec.ts`, `realtime-run.spec.ts`. Для новой арены — дымовой сценарий: арена открывается и играется до конца цели.
- Фикстуры журналов в `tests/fixtures/` не перезаписывать без причины.
- Документы: таблица арен и пулов в `docs/realtime-slice.md`, раздел арен в `docs/realtime-stage3.md` или `docs/realtime-phase-a.md`, замеры с датой и указанием изменения; `README.md`, если изменились команды. Скилл `docs-sync`.
