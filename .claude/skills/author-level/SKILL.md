# Авторский бой: $ARGUMENTS

Прочитать перед правкой:
- `docs/level-design-guide.md` — методика, карточка боя, целевые метрики;
- `docs/biomes/forest-map.md` — карта, правила похода, раздел «Как добавить бой узла»;
- профильный `docs/levels/*.md` и `docs/level-metrics.md`;
- при устройствах — `docs/devices.md`.

## Порядок

1. **Карточка боя** (раздел 6 руководства): тип боя, одна идея, роли, главное решение, что должен провалить урезанный агент, целевые метрики.
2. **Расстановка** через `authoredLesson` в реестре `src/game/run/battles/*.ts`:
   - `trunk.ts` — ствол;
   - `beasts.ts` — звериная тропа и логово;
   - `goblins.ts` — засека и лагерь;
   - `shared.ts` — общие бои троп и Тюремщик;
   - `bosses.ts` — Тролль и Главарь.
3. **Привязка к узлу:** `content: battle('<id>')` в `FOREST_MAP` (`src/game/run/forestMap.ts`).
4. **Анализ:** `npm run analyze:levels -- --node <id>` (непривязанный бой — с `--row R`) или `--nodes`. Повторять до попадания в диапазоны раздела 9 руководства. Менять расстановку, а не правила.
5. **Проверка:** маршруты реальными командами (ниже), тесты, документы с датированными метриками «до/после».

## Формат

Построитель — `authoredLesson(spec)` в `src/game/lessonBuilder.ts`:

| Символ | Значение |
|---|---|
| `#` | стена |
| `H` | кот (ровно один) |
| `R` `G` `B` `O` `V` | пассивные слабые враги цветов 0, 1, 2, 3, 4 (0 HP). Пассивность действует только на рядах 1–4 |
| `r` `g` `b` `o` `v` | вооружённые слабые враги тех же цветов |
| любой другой | задаётся в `legend`: `{color, hp, armed, target, kind, variant, terrain, device: {kind, charges, targets: ['C4']}, door}` |

- **`terrain`:**
  - `puddle`, `thorns` — проходимая земля под сущностью;
  - `tree`, `pond`, `campfire` — непроходимая декорация, клетка без сущности.
- **HP обязателен** для особых врагов (`variant`, `ranged`, `boss`).
- **Поля spec:**
  - `id` — латиница, дефисы;
  - `seed`, `palette` (по умолчанию — цвета карты), `goals` (по умолчанию — все отмеченные цели), `completion` (по умолчанию `exit`, если на карте есть дверь `{ door: true }`, иначе `direct`), `spikedEdges`.
- **Каждая проходимая клетка, кроме кота,** занята врагом, устройством или дверью.
- **Бой не задаёт** инструменты, энергию, предметы и seed пополнения: их задаёт поход. `validateNodeBattle` отклоняет стартовый инвентарь.

## Правила из AGENTS.md, которые нельзя нарушать

- **Палитра пополнения — по ряду карты:**
  - ряды 1–2 — 2 цвета, 3–4 — 3, 5–8 — 4, с 9-го — 5;
  - к ней добавляются цвета авторской расстановки (`authoredRefillPalette`).
- **Стартовая расстановка подготовлена заранее и разноцветна.** Маршрут выделяется планировкой и расположением противников, а не заливкой поля одним цветом.
- **Новые цвета размещаются связанными группами.** Маршруты проверяются реальными ходами.
- **Фиксирована только стартовая расстановка.** Пополнение случайно по seed и весам палитры. Никаких цветовых таблиц по координатам и `refillColors`/`refillCandidates`.
- **Выжившие не перекрашиваются.** Стартовые враги не перекрашиваются и не ослабляются генерацией. Стартовая карта без обычной цепи отклоняется целиком: `startRunBattle` возвращает `false`.
- **Не менять игровые правила** ради удобства заранее выбранного маршрута или простоты теста.

## Проверка маршрута

1. **Скрипт** в `.scratch/` (папка в `.gitignore`): `startNodeBattle('<id>', { seed })` из `src/game/testing/fixtures.ts`, затем реальные `beginChain`/`extendChain`/`releaseChain` со сверкой с `preview(path)`: `hits`, `power`, `pitCells`, `playerDies`.
2. **Задуманное решение проходит;** очевидные неверные маршруты не дают победы случайно.
3. **После каждого хода** `hasOrdinaryChain(state)` из `boardGeneration.ts`: ход не упирается в тупик.
4. **Несколько seed:** решение не должно зависеть от удачного пополнения, если бой этого не предполагает.
5. **В браузере при 1280×720** (скилл `run` или `claude-in-chrome`): поле, цель, HP/энергия и действия видны на первом экране, подсказка не перегружает экран.

## Обновить

- **Тесты боёв карты:** `test:forest-run` и наборы фракций и боссов (список — `package.json`, скрипты `test:*`). Ожидания менять только там, где изменилось намеренное поведение.
- **Документы:**
  - профильный `docs/levels/*.md`;
  - таблица узлов в `docs/biomes/forest-map.md`;
  - `docs/gdd.md`, если бой меняет состав карты;
  - краткая память проекта в `AGENTS.md`, если изменился состав карты.

Для JSON редактора (`customLevel.ts`) веса палитры пользователя сохраняются: нулевой вес исключает цвет, пока его не активирует `extraColors`.
