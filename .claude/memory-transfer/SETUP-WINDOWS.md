# Настройка проекта Ashen Oath на Windows 11 — инструкция для Claude Code

Этот файл — задание для Claude Code на новой машине. Пользователь запускает Claude Code в корне клонированного репозитория и пишет: «Выполни .claude/memory-transfer/SETUP-WINDOWS.md».

Контекст: проект переехал 14.10.2026 с macOS на Windows 11. Ветка работы — `forest-biome-design`. Удалённый репозиторий — `git@github.com:xuryrg2034/heroes_journey.git`, он ПУБЛИЧНЫЙ. Память Claude Code о проекте лежит в `.claude/memory-transfer/` (описание — `README.md` рядом).

## Правила выполнения

- Отчёт пользователю — на русском, примерно 80 % текста по правилам ASD-STE100: короткие фразы, одна мысль в фразе, списки для шагов.
- Не вводи пароли, токены и ключи сам. Если шаг их требует (SSH-ключ, вход в GitHub, вход в Claude Code), опиши, что сделать, и попроси пользователя выполнить шаг самому. Команду в этой сессии он может запустить с префиксом `!`.
- Ничего не перезаписывай и не удаляй без ответа пользователя, если цель уже существует.
- Шаг не прошёл — остановись на нём, покажи вывод ошибки и предложи исправление. Не пропускай шаг молча.

## Часть 1. Окружение

1. Проверь инструменты: `git --version`, `node -v`, `npm -v`, `bash --version`.
   - Git for Windows нужен с Git Bash: скрипт полной проверки `.claude/skills/verify-all/scripts/verify.sh` написан для bash.
   - Node нужен версии 22 (на старой машине стояла v22.20.0).
   - Если инструмента нет или версия не та, скажи пользователю, что установить. Не ставь программы сам без его согласия.
2. Проверь git:
   - `git -C <корень> remote -v` показывает `origin` на `github.com:xuryrg2034/heroes_journey.git`;
   - `git -C <корень> fetch` проходит. Если нет доступа по SSH, попроси пользователя создать ключ (`ssh-keygen -t ed25519`) и добавить публичный ключ в GitHub, потом повтори;
   - текущая ветка — `forest-biome-design`, она совпадает с `origin/forest-biome-design`. Если ветка другая, переключи на неё (дерево новое, локальных изменений нет — сначала проверь `git status`);
   - `git config user.name` и `user.email` заданы. Если нет — попроси пользователя задать их сам.
3. Установи зависимости в корне: `npm ci`, затем `npx playwright install chromium`.
4. Быстрая проверка:
   - `npx tsc --noEmit`;
   - `npm run build`;
   - один тест Node, например `npm run test:realtime-feats`.
   Полную приёмку (`verify.sh --browser` и Playwright ×3, около двух часов) не запускай без просьбы пользователя.
5. Playwright запускается с конфигом реального времени: `npx playwright test -c playwright.realtime.config.ts`. Если в окружении заданы `HTTP_PROXY` или `HTTPS_PROXY`, задай и `NO_PROXY=127.0.0.1,localhost`, иначе веб-сервер теста не стартует и тесты не идут.

## Часть 2. Память Claude Code

6. Найди свою папку памяти проекта. Путь указан в твоём системном промпте, в разделе о памяти. Если его там нет, путь такой: `%USERPROFILE%\.claude\projects\<полный путь к корню репозитория, где каждый символ, кроме букв и цифр, заменён на «-»>\memory\`. Создай папку, если её нет.
7. Если в папке уже есть файлы, покажи их список и дождись ответа пользователя.
8. Скопируй в неё все файлы из `.claude/memory-transfer/memory/`, включая `MEMORY.md`. Содержимое не меняй.
9. Скопируй `.claude/memory-transfer/user-skills/council/SKILL.md` в `%USERPROFILE%\.claude\skills\council\SKILL.md`.
10. Если файла `.claude\settings.local.json` нет, создай его из `.claude/memory-transfer/settings.local.json.example`. Если файл есть, добавь в `permissions.allow` недостающие правила из примера.
11. Прочитай каждый перенесённый файл памяти и сверь его с этой машиной. Память писали на macOS: пути `/private/tmp/...` и `~/.claude/...`, переменная `HTTP_PROXY`, bash-скрипты, ссылки `node_modules` на общую установку. Если правило здесь не действует или требует другой команды, допиши в этот файл памяти короткую заметку «Windows 11 (дата): …». Само правило не удаляй.
12. Сборка артефакта для плейтеста: прочитай `tools/artifact/README.md` и проверь, что `node tools/artifact/build.mjs` и `node tools/artifact/smoke.mjs` проходят на этой машине. Артефакт не публикуй без просьбы пользователя. Если сборка или дымовые проверки падают, запиши это в отчёт.

## Часть 3. Отчёт

13. Дай пользователю короткий отчёт:

    - что скопировано и куда (полные пути);
    - результаты быстрой проверки (шаг 4) и сборки артефакта (шаг 12);
