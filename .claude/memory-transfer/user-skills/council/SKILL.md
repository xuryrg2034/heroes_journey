# Council — независимый совет агентов по одному вопросу

Цель: дать пользователю решение, проверенное с нескольких сторон, а не одно мнение. Члены совета работают **параллельно и независимо** (не видят ответов друг друга), затем ты сводишь позиции в вердикт.

## 1. Сформулируй вопрос и бриф (сам, до запуска агентов)
- Вопрос — одним предложением, как решение «делать X или нет / какой из вариантов». Если пользователь написал «council this» без вопроса — возьми последний открытый вопрос/предложение из разговора (часто твой собственный) и скажи, какой именно.
- Бриф для всех членов (одинаковый): контекст из разговора (факты, цифры, ограничения, решения пользователя, которые НЕ пересматриваются), пути к файлам/данным, которые стоит прочитать, и что считается успехом. Агенты не видят разговор — бриф должен быть самодостаточным. Не включай персональные данные, которые не нужны для решения.
- Указывай в брифе, что надо разделять FACT / ASSUMPTION / INTERPRETATION, а нет данных → «неизвестно».

## 2. Состав (по умолчанию 3; «council N» — N от 2 до 5)
Подбери роли под вопрос так, чтобы они реально тянули в разные стороны. Базовый набор:
1. **Адвокат** — сильнейшие аргументы ЗА предложение, с цифрами.
2. **Скептик** — адвокат дьявола: риски, скрытые издержки, когда это ошибка; честно помечает слабые аргументы как слабые.
3. **Практик / исполнитель** — как именно это сделать, что сломается при внедрении, сколько стоит/даёт в числах, альтернативы проще.
Дополнительно по теме: «налоги/право», «пользователь-новичок (поведенческие риски)», «долгий горизонт (10–20 лет)», «стоимость/комиссии», «безопасность» и т. п.

## 3. Запуск
- Используй Agent tool, ВСЕ члены — в одном сообщении (параллельно), `subagent_type: general-purpose` (или подходящий проектный агент), модель — по сложности (по умолчанию самая сильная доступная для рассуждений).
- Каждому: бриф + его роль + жёсткие правила: только чтение (ничего не менять в файлах/системах, не делать коммитов, не отправлять сообщений, не совершать сделок), ответ по-русски, до ~35 строк, первая строка — **позиция одной фразой**, затем аргументы с оценкой силы (сильный/средний/слабый) и числами, затем «что проверить пользователю». Запрещено ссылаться на мнения других членов (их нет).
- Если пользователь просил фоновый режим или вопрос большой — запускай в фоне и сообщи, что совет заседает.

## 4. Свод (твой ответ пользователю)
1. **Вердикт** — 1–2 предложения: что делать (или «решение ваше, вот развилка»), с главной причиной.
2. **Где совет согласен** — 2–4 пункта.
3. **Где разошлись и как разрешено** — по каждому расхождению: позиции, чей аргумент сильнее и почему (данные > мнения); если не разрешимо без пользователя — прямо вопрос к нему.
4. **Цифры** — ключевые числа, на которые опирается вердикт (с источником: файл/расчёт/документ).
5. **Что сделать дальше** — конкретные шаги; если нужно действие с последствиями (правка файлов, коммит, деньги) — предложи и спроси, а не делай молча, если пользователь заранее не разрешил.
Пиши простым языком, без жаргона; не копируй ответы членов целиком — сжимай. Не выдумывай: если член совета привёл цифру без источника и ты не можешь проверить — помечай «не проверено».

## 5. Ограничения
- Совет не отменяет правил проекта (например, в инвест-проекте — никаких BUY/SELL и сделок, решение за пользователем).
- Не создавай больше 5 членов; повторный раунд («ответ на возражения») — только если пользователь попросит или расхождение критично.
