# Логи и метрики плейтеста реального времени

**Статус: задание дизайна, 10.10.2026. Реализованы контракт Т0, приёмник dev-сервера ТC, отчёт ТB и запись в браузере ТA (раздел 8); 11.10.2026 — поля петли «Печать» и случайных шагов назад (раздел 8, последний подраздел).** Решения пользователя 10.10.2026: анкеты после похода нет; канал через артефакт — сразу.

## 1. Цель

Большую часть фактов плейтеста дизайн читает из логов. Пользователь и тестеры пишут только ощущения.

## 2. Принцип

- **Игра пишет мало, отчёт считает много.** Игра сохраняет журнал каждого боя (seed + команды, `Journal` из `sim/simulation.ts`) и короткие сводки. Скрипт в Node повторяет бои по журналу и считает метрики. Новые метрики можно посчитать и по старым логам.
- **Запись не меняет игру.** Хэш боя прежний. Запись живёт в слое вида и похода, не в `sim/`.
- Только игровые данные. Личных данных нет; имя тестера — по желанию.
- У пошаговой игры была своя телеметрия; она удалена вместе с игрой (11.10.2026, тег `turn-based-final`).

## 3. Записи

У каждой записи: версия схемы, коммит сборки, версия Params, id сессии браузера, время.

**Поход** (`run`): seed, итог (победа, поражение, брошен), дальний ряд, причина смерти (вид врага, способность, аффикс элиты), HP по узлам, выборы (дар, талисманы, молот, реликвия, клятва — что предлагали, что взято, от чего отказ), торговец, привал, события, арена и состав каждого узла, сборка в конце.

**Бой** (`fight`): узел, арена, состав, ряд, длительность, итог, HP в начале и в конце, хэш в конце, плюс сводка:

| Группа | Метрики |
| --- | --- |
| Урон | По источникам: касание, стрела, рывок кабана, бросок волка, прыжок рыси, взрыв сапёра, иглы, огонь элиты, терновник. Моменты HP ≤ 3. |
| Читаемость угроз | Каждое предупреждение (метка лучника, полоса кабана, бросок волка, прыжок рыси, круг сапёра) с героем в зоне при появлении: попал или увернулся; время выхода из зоны. |
| Цепь | Число цепей, длина (медиана, максимум), отмены, шаги назад (и снятые звенья, взятые снова за ≤ 0,3 с реального времени), кристаллы, смены цвета, расход фокуса и пустой фокус, цепи с выжившим в конце. Петля (песочница, `loopEnabled`): попытки замкнуть, печати, пустые печати, тел внутри каждой печати, размыкания. |
| Убийства | Цепью; инструментами игрока (молот, волна, бомба, взрыв сапёра от цепи); способностями врагов (без зачёта). |
| Сборка | Срабатывания каждого талисмана, молота, реликвии, клятвы. |
| Темп | Время до целей, после целей, до двери; врагов на арене и в кадре (среднее, максимум). |
| Движение | Путь, время на месте, в воде, в терновнике. |
| Способности | Прыжки, круговые удары, предметы по видам. |

Почти всё из сводки отчёт может пересчитать по журналу. Сводка нужна, чтобы читать без повтора и сверять повтор.

**Журнал боя** (`journal`): `Journal` целиком, частями по ≤ 200 КиБ.

**Отметка** (`note`): клавиша **N** в бою — отметка «здесь что-то не так»: номер такта, арена, бой. Без окна и текста: игра не прерывается. Короткая вспышка «отмечено» у HUD.

## 4. Каналы

Игра пишет записи в общий интерфейс приёмника. Приёмников может быть несколько. Без приёмника игра работает как раньше.

| Канал | Как | Кто подключает |
| --- | --- | --- |
| Браузер | Кольцевой буфер в `localStorage` (предел по размеру, старые журналы уходят первыми, сводки живут дольше). Кнопка «Копировать» в панели «Логи» — копирует JSON в буфер обмена (с 11.10.2026). | Ядро |
| Локальный сервер | Плагин Vite (только dev-сервер): POST записи → файлы `playtest-logs/<сессия>/<поход>/*.json` (папка в `.gitignore`). | Ядро |
| Артефакт | Страница артефакта подключает приёмник `window.__rtTelemetrySink` (объект с `write(record): Promise<void>`) и пишет в базу артефакта (`db`). Предел документа — 256 КиБ, поэтому журналы частями. Зритель без входа — приёмника нет, работает буфер браузера. | Дизайн (при сборке страницы) |

Ошибка приёмника не ломает игру: запись остаётся в буфере браузера и уходит позже.

## 5. Отчёт

`npm run realtime:report -- <папка или JSON>`:
- повторяет каждый бой по журналу и сверяет хэш (несовпадение — найденная ошибка детерминизма, отчёт её выделяет);
- считает метрики раздела 3;
- пишет markdown: походы, арены, враги, угрозы (доля уворотов по виду), предметы (предложен / взят / сработал), отметки N с ареной и тактом;
- `--at <бой> <такт>`: снимок мира и скриншот поля в этот такт (для разбора отметок).

## 6. Условия приёмки

- Хэш боя с записью и без неё одинаковый; golden — 0 расхождений.
- Запись стоит меньше 0,1 мс за такт (замер на «Большой поляне»).
- Журнал из лога повторяется в Node с тем же хэшем (тест на записанном бое из Playwright).
- Отчёт строится на тестовом наборе логов; несовпадение хэша в наборе отчёт показывает.
- Буфер браузера не выходит за предел; экспорт работает.
- Плагин Vite пишет файлы только на dev-сервере; в сборке артефакта его нет.
- README и этот документ (раздел «Реализация»).

## 7. План и решения дизайна (10.10.2026)

### Замеры к решению

- `world.events` в хэш не входят (`sim/hash.ts`); функции сигналов врагов только читают мир. **Правка `sim/` не нужна**: всё, кроме «врагов в кадре», считается в Node повтором журнала; «в кадре» — только браузер (камера зависит от окна, dt и курсора, которых нет в журнале).
- Урон по источникам уже есть в `hit.source` (касание, стрела, кабан, волк, рысь, взрыв, иглы, огонь элиты, терновник) с `enemyId`; бросок волка отличим от касания по состоянию волка на прошлом такте.
- Стоимость наблюдателя ≈ 1 мкс/такт (43 врага) при такте симуляции ≈ 77 мкс.
- Журнал: команда `sweep` на каждое событие указателя при зажатой цепи (≈ 125 Б). Бой 90 с на «Большой поляне» (цепь 64% времени): JSON 445 КиБ (60 Гц) / 881 КиБ (120 Гц); компакт без потерь + gzip — 72 / 140 КиБ. Поход без сжатия — 3,5–7 МБ (больше `localStorage`). Округлять координаты нельзя: они решают захват звеньев.
- `talismanFired` шлют все талисманы-счётчики, «Кровавая клятва» и «Клятва голода». Жернов, Тяжёлый клинок, Быстрые ноги и Широкий круг — постоянные модификаторы без срабатываний (в отчёте — «действует»); молоты — событие `hammer`.

### Дорожки

Т0 (первой): `src/realtime/telemetry/schema.ts` — типы записей, id, нарезка и склейка, кодек компактного журнала, сигнатуры сводки и хука `__realtime.replayTo`. Затем параллельно: ТC — плагин Vite (`vite/rtTelemetryPlugin.ts`, `vite.config.ts`, `.gitignore`); ТB — метрики и отчёт (`telemetry/observe.ts`, `telemetry/threats.ts`, `scripts/realtime-report.ts`, фикстуры логов); ТA — запись в браузере (`telemetry/recorder|buffer|sinks.ts`, точки записи в `view/main.ts` и `view/runView.ts`, панель «Логи», клавиша N, хук `replayTo`). Слияние: Т0 → ТC → ТB → ТA.

### Схема и id

Шапка: `schema`, `id`, `kind` (`run` | `fight` | `journal` | `note`), `build` (коммит, `+dirty`), `params {storage, hash}`, `session`, `run`, `at` (ISO), `tester?`. id — путь из сегментов `[A-Za-z0-9_-]` ≤ 64: `S/R/run`, `S/R/f03-n5a-a1/fight`, `S/R/f03-n5a-a1/j0of1`, `S/R/f03-n5a-a1/n12345` (S — сессия, R — поход `r<время base36>-<seed hex>` или `sandbox`, `aK` — попытка арены). Повторная отправка — тот же id. Целостность журнала: число частей, длина, `digest` склейки, хэш повтора = `endHash`. Приёмник артефакта сам переводит id в `telemetry/<id с «/» → «__»>` (в базе — чётное число сегментов).

### Ответы (решения дизайна 10.10.2026)

1. Журнал — компактный без потерь + gzip (`CompressionStream`) + base64: обычный бой — одна часть; резка на части ≤ 200 000 символов — для длинных боёв. Ввод не округляется.
2. Буфер браузера: **журналы — в IndexedDB**, сводки и отметки — в `localStorage` (одна запись — один ключ, индекс; вытеснение: доставленные журналы → недоставленные → отметки → сводки).
3. Params — один раз на поход (в записи `run`), журнал ссылается по хэшу.
4. Кнопка «Копировать» кладёт JSON экспорта в буфер обмена (**изменено 11.10.2026, решение пользователя**: раньше «Экспорт» скачивал файл). Порядок: (а) `navigator.clipboard.write([new ClipboardItem({'text/plain': Promise<Blob>})])` — вызов синхронно в обработчике клика до любого `await`, текст отдаётся промисом (экспорт асинхронный, IndexedDB, а Safari и Firefox теряют жест пользователя после `await`); (б) нет или упало — `navigator.clipboard.writeText(text)`; (в) буфера нет — прежний путь: хук страницы `window.__rtTelemetryExport?.(filename, text): Promise<void>` (в артефакте скачивание блокируется, пока страница не объявит возможность), без хука — ссылка `<a download>`; статус «Буфер недоступен — сохранён файл». Успех: «Скопировано: N записей, X КиБ. Вставьте в сообщение.» (слово «запись» склоняется по N) Предупреждения о размере нет (буфер до 2 МиБ). Содержимое — тот же JSON `makeExport`; `npm run realtime:report` читает его из файла, как раньше (вставленный текст сохраняют в `.json`).
5. Панель «Логи»: в шапке карты похода, в итоге похода, в меню песочницы; в бою кнопки нет. В панели — необязательное **имя тестера** (хранится в `localStorage`, идёт в `tester`).
6. Плагин Vite: только `serve`; POST `/__rt-telemetry` только с loopback, проверка `Origin`, `Content-Type: application/json`, тело ≤ 512 КиБ; файлы `playtest-logs/<сессия>/<поход>/*.json` (в `.gitignore`). LAN — флагом `RT_TELEMETRY_LAN=1` (по умолчанию выключен; дизайн включает его на сервере плейтеста — пользователь играет и с другого компьютера в локальной сети).
7. Перезагрузка посреди боя: на `pagehide` — частичный журнал с `outcome: 'unload'`, только в буфер.
8. Бои песочницы пишутся с `run: 'sandbox'`, в отчёте — отдельный раздел.
9. Части журнала режутся по символам.
10. Волк — предупреждение на стаю.
11. Метка лучника и фитиль от касания (герой в зоне всегда) — доля уворотов от всех таких предупреждений.
12. «Защищён» (тело в зоне в такт удара, но неуязвимость/щит цепи/проход/прыжок) — отдельная категория, не уворот.
13. «Врагов в кадре» точно считает браузер (в сводке); Node — приближение, размер вида — в записи боя.
14. Поле `via: 'rush'` у `hit` не добавляется: бросок волка классифицирует Node.

Определение исходов предупреждения: **попал** — удар этого врага этим источником; **защищён** — см. п. 12; **увернулся** — в такт удара тело вне зоны; **прервано** — враг умер, отброшен или бой кончился (холод — не исход: таймер ждёт). Время выхода — такты от фиксации зоны до первого такта вне зоны.

Уточнения дизайна 10.10.2026 (ответы на вопросы дорожки ТB):
- **Волк: время выхода — от начала воя.** Медиана выхода в отчёте тоже считается от воя. Такт фиксации полосы (начало рывка первого волка стаи) пишется в предупреждение отдельным полем `lockTick`; в отчёте оно пока не выводится.
- **Укрытие с подтипом.** Рывок кабана или волка, который остановился раньше своей дальности, — «увернулся», `reason: 'cover'` («укрытие»), с подтипом `coverKind`: `wall` — стена или дерево, `cliff` — край обрыва. Обрыв тоже укрытие, а не «прервано». Отчёт показывает укрытия по подтипам («укрытие: стена N, обрыв M»): дизайн смотрит, как часто обрыв останавливает рывок без манёвра игрока.
- **Длина цепи** — число звеньев-врагов при отпускании. Кристаллы, кнопки, дверь, жаровни и добыча в длину не входят.

Приёмник артефакта: `window.__rtTelemetrySink = { write(record): Promise<void> }`, проверяется лениво перед каждой отправкой; ошибка не ломает игру — запись ждёт в буфере, повтор с отступом 1 → 30 с.

## 8. Реализация

(заполняют дорожки Т0, ТC, ТB, ТA)

### Т0 — контракт (10.10.2026)

Код: `src/realtime/telemetry/schema.ts` (типы, id, экспорт, сводка, наблюдатель, хук) и `src/realtime/telemetry/codec.ts` (кодек журнала, gzip, части; реэкспорт из `schema.ts`). Без DOM: работает в браузере и в Node. `sim/` не менялся. Проверка — `npm run test:realtime-telemetry` (`schema.spec.ts`).

**Записи.** `RtRecord = RunRecord | FightRecord | JournalPart | NoteRecord`, шапка `RtHeader` (`schema: 1`, `id`, `kind`, `build`, `params {storage, hash}`, `session`, `run`, `at`, `tester?`).
- `RunRecord`: `seed`, `outcome` (`victory` | `defeat` | `abandoned` | `open`), `farRow`, `death` (`enemy?`, `source` = `hit.source`, `elite?`, `affixes?`, `fight?`, `tick?`) или `null`, `nodes` (узел, ряд, тип, HP на входе и выходе, максимум, арена, состав, ключ боя, событие), `choices` (`nodeId`, `source`, `offered`, `taken`, `refused`), `kit` — сборка в конце, `fights` — ключи боёв, `runParams` — сами Params, один раз на поход. Имена `kit` и `runParams` выбраны потому, что `build` и `params` заняты шапкой (коммит и `{storage, hash}`).
- `FightRecord`: `fight` (ключ), `nodeId?`, `arena`, `roster?`, `row?`, `seed`, `outcome` (`victory` | `defeat` | `restart` | `menu` | `unload`), `ticks`, `time`, `hpIn`, `hpOut`, `endHash`, `journal {parts, chars, digest, encoding}`, `view? {w, h}` (размер вида в единицах арены), `summary: FightSummary`.
- `JournalPart`: `fight`, `index`, `count`, `digest` и `encoding` всей склейки, `data`.
- `NoteRecord`: `fight`, `tick`, `arena`, `hero {x, y}`.
- `checkRecord(value)` — неглубокая проверка записи: шапка; id совпадает с видом, сессией, походом, боем, номером части или тактом; обязательные поля. Возвращает первую проблему или `null`.
- Экспорт: `makeExport(session, records, exportedAt)` → `{format: 'ashen-oath-rt-telemetry', version: 1, exportedAt, session, records}`; `parseExport(text)` проверяет формат и каждую запись.
- Каналы: `RtTelemetrySink { name?, write(record): Promise<void> }`, `RtTelemetryExportHook = (filename, text) => Promise<void>`, `RtTelemetryWindow` — что искать на `window` (`__rtTelemetrySink`, `__rtTelemetryExport`).

**id.** Сегмент — `ID_SEGMENT_RE` (`[A-Za-z0-9_-]{1,64}`), весь id — `RECORD_ID_RE`. `isRecordId(id)` — проверка для плагина Vite: нет `.`, пустых сегментов, обратных слэшей, лишних частей; номер части меньше их числа. `parseRecordId(id)` разбирает id. Построение: `sessionKey(timeMs, salt)` → `s<base36>-<hex>`, `runKey(timeMs, seed)` → `r<base36>-<seed hex>`, `SANDBOX_RUN = 'sandbox'`, `fightKey(index, nodeId, attempt)` → `f03-n5a-a1` (без узла — `x`; чужие символы узла → `_`; длинный узел режется до 64), `runRecordId`, `fightRecordId`, `journalPartId(…, i, n)`, `noteRecordId(…, tick)`. На плохом сегменте построители бросают ошибку.

**Журнал.** `encodeJournal(journal, paramsRef?)` — компактный JSON без потерь. Команда — массив `[разница тактов, код, …поля]`. `sweep` идёт без `fx, fy`, если они равны прошлой точке указателя. `drag` идёт без `mode: 'full'`. Команда другой формы (отладка, тестовые, поле, добавленное позже) идёт целиком: `[dt, 'o', {…}]`. Прочие поля журнала (`hero`, `loadout`, `roster`, будущие) — как есть. Числа не округляются. С `paramsRef` Params опускаются, только если `paramsHash(journal.params) === paramsRef`; иначе остаются целиком.
- `decodeJournal(text, params?)` — точный журнал (и обычный JSON `Journal`). Для ссылки нужны Params записи похода; их хэш сверяется.
- `paramsHash(params)` — `hashText` канонического JSON (ключи по алфавиту).
- `gzipBase64` / `gunzipBase64` — `CompressionStream` + base64. В Node 22.20 проекта они есть.
- `splitParts(text, max = 200 000)` режет по символам, не внутри суррогатной пары. `assembleParts(parts, {parts, chars, digest})` сверяет число частей, длину и `digest = hashText(склейки)`.
- Обёртки: `packJournal(journal, {paramsRef?, encoding?, max?})` → `{parts, meta}` (по умолчанию `compact+gzip+b64`); `unpackJournal(parts, meta, params?)`; `orderedParts(partRecords, fight, digest)` — части по порядку из записей в любом порядке.

**Сигнатуры для других дорожек.** `FightSummary` — группы раздела 3: урон по источникам, удары, моменты HP ≤ 3; угрозы по видам (`ThreatTally`: предупреждён, попал, увернулся, защищён, прервано, такты выхода); цепь; убийства цепью, инструментами, способностями врагов; срабатывания сборки и «действует»; темп и `inView? {avg, max}`; движение; способности. `emptyFightSummary()` — пустая сводка. `withSummaryDefaults(summary)` (с 11.10.2026) — сводка записи старой сборки с полями, добавленными позже, из пустой сводки (правило — последний подраздел раздела 8). `FightObserver { command(cmd, world), tick(world), summary() }`, `FightObserverFactory = (world) => FightObserver`, `nullObserver` — пустая реализация до ТB. `ReplayTo = (journal, tick) => Promise<void>` — хук вида `__realtime.replayTo` (реализует ТA).

### ТB: метрики и отчёт (реализовано 10.10.2026)

Код: `src/realtime/telemetry/observe.ts` (наблюдатель боя), `threats.ts` (предупреждения, только Node), `report.ts` (сборка, повтор, markdown; без файловой системы), CLI `scripts/realtime-report.ts`, генератор фикстур `scripts/realtime-make-log-fixtures.ts`, фикстуры `tests/fixtures/realtime-logs/`. `sim/` и `schema.ts` не менялись: полей `FightSummary` из Т0 хватило.

**Наблюдатель** (`createFightObserver(world)`, он же `fightObserver: FightObserverFactory`). Чистый, без DOM. Вызывается после каждой команды (`command`) и каждого такта (`tick`). События читает курсором: помнит последнее прочитанное событие по идентичности. Вид очищает `world.events` раз в кадр, повтор в Node — после такта; курсор работает в обоих случаях. Определения:
- Урон — каждый `hit` по `hit.source`. Удар `wolf` от волка, который на прошлом такте был в рывке, — `wolf-rush` (бросок волка, решение 14). Касание волка остаётся `wolf`. `lowHp` — такт или команда с ударом, после которых HP ≤ 3 (`tick` — сыгранные такты, `world.tick`).
- Цепь — проход, который начался (`world.move` вида `dash`). Длина — число звеньев-врагов при отпускании; кристаллы, кнопки, дверь, жаровни и добыча не считаются (раздел 7, уточнения 10.10.2026). Смены цвета — смены цвета между соседними врагами отпущенной цепи. Кристаллы — выпавшие (`crystal`). Отмена — команда опустошила рисуемую цепь без прохода. Шаг назад — команда укоротила цепь, но не опустошила. Расход фокуса — реальные секунды фокуса за такты фокуса. Пустой фокус — такты с рисуемой цепью и фокусом 0. Цепь с выжившим — проход ударил звено, которое выжило (с 11.10.2026 удар по пластине элиты, `chainHit.plates`, — не выживший: цепь идёт сквозь элиту). Петля и повторы после шага назад (с 11.10.2026) — последний подраздел раздела 8.
- Убийства (`kill`): `chain` — цепь (и выживший, сброшенный цепью в обрыв). Другой зачтённый источник — инструмент игрока (`bomb`, `spin`, `blast` сапёра, убитого игроком, `wave`, `hammer-*`). Незачтённые — способности врагов.
- Сборка: `talismanFired` по id; событие `hammer` — молот похода; `ward` — `ash-ward`. `active` — талисманы и реликвии набора без своих срабатываний («Жернов», «Тяжёлый клинок», «Быстрые ноги», «Широкий круг», «Точильный камень» …).
- Темп: игровые секунды до целей, от целей до конца, до двери (только победа); врагов на арене за такт (среднее, максимум). «В кадре» (`inView`) наблюдатель не считает: его добавляет вид (ТA).
- Движение: путь героя (ходьба, проход, прыжок, отброс; `teleport` — не путь); игровые секунды на месте, в воде (центр героя), в терновнике.
- Способности: события `jump`, `spin`, `item` по видам.

**Угрозы** (`ThreatTracker`, только Node). Предупреждение считается, только если герой в зоне при появлении. Зоны:
- метка лучника — круг `archerMarkRadius` + тело героя (в журналах без `archerPoint` — линия);
- кабан — полоса от кабана: `boarRange` в замахе, остаток в рывке (полоса укорачивается); дотяг — касание + `CONTACT_SLACK`;
- волк — одно предупреждение на стаю (волки, завывшие в один такт). Пока волк воет — зона в пределах длины его броска от него (линия смотрит на героя). В рывке — его закреплённая линия. Длина броска — `wolfRushLength` симуляции (с 11.10.2026): `wolfRushRange` (4), в вое, к которому присоединился вожак-элита, — `wolfLeaderThrow` (5); раньше отчёт брал 4 и для вожака;
- рысь — линия прыжка (в прыжке — остаток);
- сапёр — круг `sapperRadius` + тело героя. Фитиль от касания и его взрыв — одно предупреждение. Фитиль убитого сапёра — предупреждение, если герой в круге. Взрыв с задержкой 0 — `sapper-instant` («без предупреждения»).

Исходы (решения 10.10.2026): **попал** — удар этого врага этим источником. **Защищён** — тело в зоне в такт удара, удара нет (`stats.boarHits` вырос без `hit`; рысь приземлилась рядом; волк добежал; проход или прыжок сквозь рывок). **Увернулся** — в такт удара тело вне зоны. Укрытие — `reason: 'cover'` с `coverKind`: рывок кабана остановлен раньше дальности — `cliff`, если следующий шаг уходил в обрыв (а стены там нет), иначе `wall` (стена или дерево); у стаи волков укрытие — когда каждый волк, который бежал, остановлен раньше дальности (стена — волк уходит назад; обрыв — волк выходит из кольца, `away`), подтип `cliff`, если хотя бы одного остановил обрыв, иначе `wall`; если хоть один волк добежал до конца дальности — просто «увернулся». **Прервано** — враг умер, отброшен, сбросил атаку (волки: холод, отброс, стая распалась), бой кончился или журнал оборвался. Холод — не исход: замёрзшие лучник, кабан, рысь, сапёр ждут. Время выхода — такты от появления зоны (у волка — от начала воя) до первого такта вне неё; также игровые и реальные секунды (`Simulation.nextTickCost()`). В сводку (`ThreatTally.exitTicks`) идут такты уворотов. У стаи — `lockTick`: такт, когда первый волк начал рывок (полоса закреплена); в отчёт не выводится.

**Отчёт** — `npm run realtime:report -- <папка или JSON> […] [--out <папка>] [--at <бой> <такт>]`.

**Шапка.** `session` — `crypto.randomUUID()` в `sessionStorage` (`ashen-oath-rt-tlm-v1:session`; без него — `sessionKey(время, getRandomValues)`). Дублированная вкладка копирует `sessionStorage`, поэтому при загрузке (и при возврате из bfcache) страница спрашивает другие вкладки через `BroadcastChannel('ashen-oath-rt-tlm-v1')` «у кого сессия X»; если вкладка с X ответила, спросившая берёт новую сессию. Без `BroadcastChannel` сессия остаётся прежней (с ревью 10.10.2026). `run` — ключ похода (`runKey(время старта, seed)`) в отдельном мета-ключе `ashen-oath-rt-tlm-v1:run-meta` (сохранение похода `RtRunState` не менялось); песочница — `sandbox`. `build` — `__RT_BUILD__` (вне Vite — `unknown`). `params` — `{storage: 'ashen-oath-realtime-params-v17', hash: paramsHash(Params)}`. `tester` — имя из панели «Логи» (`ashen-oath-rt-tlm-v1:tester`), если задано.

**Бой.**
- Ключ: в походе `fightKey(номер боя в походе, узел, попытка узла)` (перезагрузка посреди арены — следующая попытка); в песочнице `fightKey(номер боя в сессии браузера, нет узла, запуск этой арены подряд)`.
- Конец боя (победа, поражение) — в кадре, где бой кончился: `exportJournal()` и `hash()` вызываются вместе (после конца боя такты идут). В походе запись идёт до `recordRunArena`, чтобы причина смерти попала в поход.
- Выход без итога: `R` (`restart`), запуск другой арены из меню (`menu`), `replayTo` в песочнице (`menu`). Бой из 0 тактов без итога не пишется.
- `pagehide` посреди боя: тело записи и компактный журнал (без gzip: `CompressionStream` асинхронный) синхронно уходят в `localStorage` под ключ этого боя (`ashen-oath-rt-tlm-v1:unload:<сессия>/<поход>/<бой>`, до 1,5 млн символов); следующая загрузка страницы упаковывает все такие тайники (и старый общий ключ `…:unload`) в буфер с `outcome: 'unload'` и прежними session и tester.
- Возврат из bfcache (`pageshow` с `persisted`): тайник этого боя удаляется, запись боя продолжается, итог пишется как обычно (с ревью 10.10.2026).
- Журнал — `packJournal` (компакт + gzip + base64, части ≤ 200 000 символов). В походе Params журнала — ссылкой на `runParams` записи похода (если хэши совпали; иначе целиком), в песочнице — в журнале.
- `view` — размер вида камеры `{w, h}` в единицах арены в конце боя.

**Сводка.** Наблюдатель — `fightObserver` дорожки ТB (`telemetry/observe.ts`, строка `FIGHT_OBSERVER` в `main.ts`). `FightTap` зовёт его так же, как повтор отчёта (`analyzeJournal`): `tick` — один раз после каждого такта, `command` — после каждой записанной в журнал команды (команда «удержанного указателя», не попавшая в журнал, наблюдателю не показывается). Вид зовёт `FightTap` перед каждым тактом (`beforeTick`), перед каждой командой и перед очисткой `world.events` в конце кадра, поэтому такт виден таким, каким кончился, и его события ещё в списке (наблюдатель читает новые события курсором). Совпадение проверено: на двух журналах браузера при случайной нарезке на кадры наблюдатель видит те же такты, команды и новые события, что и в повторе отчёта, и сводка совпадает со сводкой `analyzeJournal` (`recorder.spec.ts`); на бою из Playwright сводка браузера равна сводке повтора, кроме `inView` и `threats` (`tests/realtime-telemetry.spec.ts`). Вид добавляет `tempo.inView {avg, max}` — врагов в камере (`renderer.sees`) за кадр, взвешено по тактам кадра. Последний удар по герою (`hit`: вид врага, источник, элита, аффиксы, такт) хранится для `death` похода.

**Поход.** Наблюдатель `RunView.apply` (`runStep(before, step)`) и `newRun` (`runStarted(previous, run)`):
- узлы: `node-entered` (ряд — `runRow`, тип, HP на входе), `battle-ready` (арена, состав), `event-resolved` (событие, вариант, исход); HP на выходе и максимум — после каждого шага; ключ боя узла — при записи боя;
- выборы (`choices`, по одной записи на узел и источник; шаги одного привала, торговца, события сливаются): дар (`gift`, `nodeId: 'start'`; кнопка с собственным выбором — `gift-pick`), талисман (`talisman`), клятва или реликвия (`oath`), молот (`hammer`), находка (`find`), событие (`event`), привал (`rest`: `heal`, `craft:<предмет>`), торговец (`shop`: `heal`, `harden`, `item:<предмет>`, `talisman:<id>`); `refused` = предложено − взято;
- конец: `run-won` / `run-lost` (`death` из последнего удара боя-поражения); новый поход при открытом прежнем — прежний пишется с `abandoned`; пока поход идёт — `open`;
- запись похода (`S/R/run`) пишется заново после каждого шага (тот же id), с `runParams` и `kit` (HP, максимум, энергия, талисманы, молот, реликвии, клятва, расходники, ресурсы).

**Отметка N.** `KeyN` по `event.code` в бою (поход и песочница), только при открытой арене (не на карте, не в меню песочницы, не при открытой панели «Логи»). В симуляцию команда не идёт. Запись `note` (`fight`, `tick`, `arena`, `hero {x, y}`); у HUD на 1 с — «отмечено». В строке помощи — «`N` отметка». В песочнице при 1280×720 длинная строка помощи обрезается многоточием раньше этих слов (обрезалась и до ТA); в походе строка короче.

**Буфер** (`buffer.ts`). Части журналов — IndexedDB `ashen-oath-rt-tlm-v1`, хранилище `journals` (версия 1; без IndexedDB или при ошибке — память вкладки, экспорт их видит). Бои, походы, отметки — `localStorage`, одна запись — один ключ `ashen-oath-rt-tlm-v1:<id>`; индекс `ashen-oath-rt-tlm-v1:index` (id, вид, размер, отметки доставки по приёмникам, порядок). Предел — 2 500 000 символов JSON на все записи. Вытеснение: доставленные журналы → недоставленные журналы (части одного журнала — один `сессия/поход/бой` — вместе) → отметки → сводки (бои, походы); старые первыми. `QuotaExceededError` — вытесняются отметки и сводки на размер записи, одна повторная попытка; иначе запись живёт в памяти этой вкладки (в общий индекс не попадает), `bufferFull = true`. Запись с тем же id заменяет прежнюю и сбрасывает её отметки доставки. Несколько вкладок (с ревью 10.10.2026): каждая запись, вытеснение и отметка доставки перечитывают индекс и пишут его обратно одним синхронным шагом; ключи записей с префиксом, которых нет в индексе (сироты), добавляются в индекс и считаются в предел. При загрузке из индекса уходят записи, которых нет в хранилище (ключа `localStorage` или части журнала). «Очистить» удаляет все ключи с префиксом, кроме `session`, `tester` и `run-meta`.

**Приёмники** (`sinks.ts`). `window.__rtTelemetrySink` (имя отметки — `artifact`) читается лениво перед каждой отправкой; dev-приёмник (`dev`) — POST `/__rt-telemetry`. Очередь последовательная, старые первыми; отказ приёмника (или запись дольше 20 с) — запись остаётся, повтор этого приёмника через 1 с, затем 2, 4 … до 30 с подряд идущих отказов; успешная отправка сбрасывает отступ к 1 с (с ревью 10.10.2026). Запуск: загрузка страницы, каждая запись, появление `__rtTelemetrySink` (проверка раз в 2 с). Ошибки приёмника игре не видны.

**Панель «Логи»** (`logsPanel.ts`). Кнопка — в шапке карты похода рядом с «Песочница», в итоге похода и в меню песочницы; в бою кнопки нет. В панели: «Записей N · не доставлено M · размер» (не доставлено — записи, которые не взял хотя бы один присутствующий приёмник; без приёмников — ни один), имя тестера (необязательно), «Копировать» (изменено 11.10.2026, решение пользователя: JSON `makeExport` — в буфер обмена; порядок `ClipboardItem` с промисом → `writeText` → хук `window.__rtTelemetryExport` → `<a download>`; см. раздел 7, п. 4), «Очистить» — подтверждение в самой панели, «Закрыть» (и `Esc`). Пока панель открыта, клавиши игры не действуют.

**Хуки вида.** `__realtime.snapshot().telemetry = {records, chars, undelivered, notes, bufferFull}` (`null` — запись выключена); `__realtime.replayTo(journal, tick)` (`ReplayTo`): журнал на `tick` тактов (команды с тактом < tick — тот же мир, что снимок `--at` отчёта), `replay` с очисткой событий на всех тактах, кроме последнего, `buildArena`, `snapCamera`, пауза; текущий бой пишется как `menu`, повтор не пишется (и когда идёт дальше). Только в песочнице: в походе хук отклоняется с ошибкой «replayTo: только в песочнице …» и ничего не меняет (с ревью 10.10.2026). Для тестов — `__realtime.telemetry` (`settle`, `records`, `put`, `cost`, `resetCost`, `session`, `limit`, `exportFile`).

### Петля «Печать» и случайные шаги назад (11.10.2026, шаг 2 исследования петли)

Метрики раздела 3.3 и 6.4 `docs/realtime-loop-research.md`. Симуляция (`sim/seal.ts`, `sim/chain.ts`, коммит `748d368`) пишет события `loop` (`close` | `refused` | `open`, `kind`, `refusal?`) и `seal` (`release` | `strike`, `inside`, `links`); они не входят в хэш. `sim/` в этой задаче не менялся; наблюдатель только читает мир.

**Поля `FightSummary.chain`** (`observe.ts`):
- `closeAttempts` — жесты замыкания: события `loop` с `close` и `refused`, на первом звене и на герое. Подряд идущие одинаковые отказы (то же замыкание, та же причина) без смены рисуемой цепи между ними — одна попытка: указатель, который движется внутри круга цели, шлёт отказ на каждую точку. Смена цепи — любое изменение звеньев (шаг назад, новое звено, звено погибло), а также замыкание или размыкание.
- `seals` — отпущенные замкнутые цепи (событие `seal`, фаза `release`); `sealsEmpty` — из них с пустым `inside`; `sealInside` — число тел внутри при отпускании, по одному числу на печать, по порядку (список, как `ThreatTally.exitTicks`: медиана по многим боям считается по сырым числам). Удар в конце прохода (`strike`) не считается: внутри — то, что игрок видел при отпускании.
- `unseals` — размыкания: события `loop` с `open` без причины (указатель на последнем звене замкнутой цепи).
- `loopBreaks` — петли, разомкнутые правилом, по причине: события `loop` с `open` и `refusal`. Причины: `changed` — звено погибло, `far` / `sight` / `crossed` — замыкающее ребро больше не проходит как звено (герой ушёл, стена, пересечение), `off` — петлю выключили. В отчёте — «сорвано N» в столбце печатей.
- `backstepReadds` — звено, которое снял шаг назад (команда укоротила цепь и оставила её непустой — как `backsteps`), снова взято в ту же цепь не позже чем через 0,3 с реального времени (`BACKSTEP_READD_WINDOW`). Опустевшая цепь (отмена, отпускание) забывает снятые звенья. Реальное время такта — `SIM_DT ÷ tickScale` (такт остановки удара — `SIM_DT`) по миру перед тактом, то есть цена `Simulation.nextTickCost` (`tickRealCost` в `observe.ts`; тест сверяет их на каждом такте боя). - Убийства печатью — `kills.tools.seal` по общему правилу (`kill` с `source: 'seal'`, `credited: true`); убийствами цепи не считаются.

### Котёл (11.10.2026, казино, этап 1, пункт 1)

Правила котла — `docs/realtime-casino.md`. Симуляция (`sim/purse.ts`) пишет события `cheque` (чек цепи: `embers`, `heat`, `crystals`, `mult`, `total`, `links`, `finish`, `cauldron` после него), `purseKill` (1 уголь за убийство сборкой, `source`) и `purseDoor` (дверь: `cauldron`, `oath`, `resources` — выплата без кости). События в хэш не входят; наблюдатель только читает.

**Новое поле `FightSummary.purse`** (`observe.ts`; в записях до 11.10.2026 его нет — читаются через `withSummaryDefaults`):
- `on` — котёл включён (`params.purse`) в конце боя;
- `cauldron` — котёл в конце боя (`world.purse`);
- `embers`, `heat`, `totals` — угли, жар и итог каждого чека, по порядку (списки: медиана и максимум по многим боям считаются по сырым числам);
- `crystals` — кристаллы, разбитые в цепях (сумма `cheque.crystals`);
- `killEmbers` — угли убийств сборкой (молоты, волна, стрелы гоблина `slot`) по источнику; звенья текущего рывка сюда не входят — их угли в чеке;
- `resources` — ресурсы, которые выдала дверь без кости; `null` — выхода в дверь с котлом не было.
- `exitStep` — ступень «Раздува за дела» в двери (0–3: ×1, ×1,5, ×2, ×3; с 11.10.2026, `purseDoor.step`); `null` — выхода в дверь с правилом не было. В записях до неё поля нет — `withSummaryDefaults` читает `null`.
- `exitBy` — как герой вошёл в дверь (`purseDoor.by`, с 12.10.2026): `chain` (цепь кончилась на двери; с П3 «Финальная цепь», `doorFinale`, её чек получил +1 жар), `jump`, `walk`; пишется и без правила. `null` — выхода в дверь с котлом не было. В записях до 12.10.2026 поля нет — `withSummaryDefaults` читает `null`. Метрика П3 — доля выходов цепью.

Событие `greed` (П4 «Раздув за дела»: ступень выросла за цепь или упала от удара; `cause`, `step`, `chains`, `mult`) в сводку отдельно не идёт: ступень в двери — `exitStep`.

**Отчёт.** Раздел «Котёл» (после «Однорукого гоблина»): строки «походы», «песочница» и «всего» (только когда котёл был в обеих группах), только бои с включённым котлом. Столбцы: боёв с котлом, котёл за бой (медиана / максимум), чеков, угли на чек, жар, чек (медиана / максимум), кристаллов в цепях, угли убийств сборки по источнику, ресурсов в двери (сумма, дверей, медиана), ступень раздува в двери (двери по ступеням ×1 / ×1,5 / ×2 / ×3; «—» — дверей с правилом нет), выход в дверь (цепью / прыжком / ходьбой; «—» — записи до 12.10.2026).

**Проверки.** `src/realtime/sim/purse.spec.ts` (`test:realtime-purse`): журнал боя повторяется с наблюдателем, `purse` совпадает с чеками и котлом боя; с выключенным котлом поле пустое. `src/realtime/sim/greed.spec.ts` (`test:realtime-greed`): `exitStep` равен ступени двери, без правила `null`, старая запись читает `null`. `src/realtime/sim/doorFinale.spec.ts` (`test:realtime-door-finale`): `exitBy` — `chain`, `jump`, `walk` (и без правила), без выхода `null`, старая запись читает `null`. `recorder.spec.ts`: квота проверки вытеснения теперь считается по размеру записи боя (её размер в хранилище + 1,5 отметки), а не числом 1500 — сводка растёт с каждой новой фичей.

### Ставка клятвы (11.10.2026, казино, этап 1, пункт 2)

Правила клятвы — `docs/realtime-casino.md`, раздел «Ставка клятвы». Симуляция (`sim/oath.ts`) пишет событие `oath`: `broken` (клятва нарушена, `tick` — такт события), `met` (клятва «хотя бы раз» выполнена, `tick`) и `door` (выход в дверь: `kept`, `mult` — множитель котла 2 или 0,5). События в хэш не входят; флаги клятвы — поле мира `oath` — входят.

**Новое поле `FightSummary.oath`** (`observe.ts`; в записях до 11.10.2026 его нет — читаются через `withSummaryDefaults` как «клятвы не было»):
- `id` — клятва боя (`world.oath.id`); `null` — боя без клятвы или правило выключено;
- `kept` — итог в двери: `true` выполнена, `false` нарушена; `null` — выхода в дверь не было;
- `brokenTick` — такт нарушения (у клятвы «хотя бы раз», не выполненной к двери, — такт двери); `null` — не нарушена;
- `metTick` — такт выполнения клятвы «хотя бы раз»; `null` — не выполнена или клятва «никогда»;
- `mult` — множитель котла, который записала дверь; `null` — двери не было.

**Выбор на карточке узла.** `RunRecord.choices` получает выбор с источником `oath-stake` (`OATH_STAKE_SOURCE`, `schema.ts`): `offered` — две клятвы карточки, `taken` — взятая (пусто — «Без клятвы»), `refused` — остальные. Источник `oath` прежний: это клятвы и реликвии Тюремщика.

**Отчёт.** Раздел «Ставка клятвы» (после «Котла»): строка на клятву — предложена и взята (карточки походов), боёв с ней (походы и песочница), выполнена и нарушена в двери, медиана такта нарушения; последняя строка «без клятвы» — карточек всего и сколько ушло без клятвы. В таблице «Предметы» выбор `oath-stake` не считается.

**Проверки.** `src/realtime/sim/oath.spec.ts` (`test:realtime-oath`): журнал боя повторяется с наблюдателем, `oath` равно клятве, такту нарушения, итогу и множителю; старая сводка читается как «клятвы не было»; выбор на карточке — запись `oath-stake` (взята и «Без клятвы»).

### Кость у двери (11.10.2026, казино, этап 1, пункт 4)

Правила кости — `docs/realtime-casino.md`, раздел «Кость у двери». Это правило похода: сводка боя (`FightSummary`) не меняется. Поход пишет события шага `die-shown` (экран открыт: `cauldron`, `oath`, `face` — грань, зафиксированная при показе) и `die-resolved` (`rolled` — «Бросить» или «Забрать», `face`, `mult` — множитель кости 0,5, 2 или 1, `resources` — выплаченные виды, `base` — выплата «Забрать»).

**Выбор на экране.** `RunRecord.choices` получает выбор с источником `door-die` (`DIE_SOURCE`, `schema.ts`): `offered` — `roll` и `take`, `taken` — выбранный.

**Новое поле `RunRecord.dice`** (`schema.ts`, `RunDie`; в записях до 11.10.2026 и в походах без кости его нет) — экраны кости по порядку:
- `nodeId`, `cauldron`, `oath` — узел, котёл и множитель клятвы из записи двери;
- `face` — грань (1–6), зафиксированная при показе; пишется и при «Забрать»;
- `rolled` — `true` «Бросить», `false` «Забрать», `null` — выбора ещё нет (экран открыт);
- `mult` — множитель кости выплаты (1 у «Забрать»); `resources` — выплачено; `base` — что дал бы «Забрать». До выбора — `null`.

**Отчёт.** Раздел «Кость у двери» (после «Ставки клятвы»): одна строка по всем походам — экранов, «Бросить», «Забрать», не выбрано, выпало 1–3 и 4–6, ресурсов выплачено и сколько дал бы «Забрать» на тех же экранах. В таблице «Предметы» выбор `door-die` не считается. Столбец котла «Ресурсов в двери (без кости)» — выплата ×1.

**Проверки.** `src/realtime/run/die.spec.ts` (`test:realtime-die`): поход с двумя экранами кости («Бросить» и «Забрать») через `RtRecorder` — выбор `door-die`, `dice` с гранью, множителем, выплатой и выплатой «Забрать»; раздел отчёта по экспорту записей.

### Второе дыхание (12.10.2026, П9, только песочница)

Правило — `docs/realtime-prototype.md`, раздел 9н. В походе правило выключено, поэтому запись бывает только у боёв песочницы. Симуляция (`sim/world.ts`, `secondWind`) пишет событие `secondWind`: место героя, HP до смертельного удара (`hp`), источник удара (`source`, как в событии `hit`), ударивший (`enemyId`; `enemy` — его вид, `elite`, если он стоял на арене в момент удара). События в хэш не входят.

**Новое поле `FightSummary.secondWind`** (`schema.ts`, `SecondWindSummary`; `observe.ts`). В записях до 12.10.2026 его нет — `withSummaryDefaults` читает `null`. `null` — дыхания в бою не было. Поля:
- `tick` — такт смертельного удара (`world.secondWind.tick`);
- `hpBefore` — HP героя до этого удара;
- `source` — источник удара, как в `damage.bySource` (бросок волка — `wolf-rush`);
- `enemy`, `elite` — вид ударившего и метка элиты; нет поля — удар без врага на арене (шипы, взрыв мёртвого сапёра).

**Отчёт.** Под таблицей боёв раздела «Песочница» — одна строка, если хоть в одном бою было дыхание: боёв с ним, медиана HP до удара, источники ударов, исходы боёв после дыхания.

**Проверки.** `src/realtime/sim/secondWind.spec.ts` (`test:realtime-second-wind`): журнал боя повторяется через `analyzeJournal` (тот же путь, что у отчёта). После дыхания от касания — такт удара, HP до него, `touch`, `basic`. После дыхания от игл в цепи — `quills`, `porcupine`. Бой без дыхания (удар не смертельный или правило выключено) — `null`. Старая сводка читается как `null`.
