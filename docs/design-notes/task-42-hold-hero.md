# Задача 42. Неподвижный курсор у героя ничего не берёт

**Статус: спека дизайна, 16.10.2026. Не реализовано.** Продолжение задачи 39 ([task-39-hold-nearest.md](task-39-hold-nearest.md)). Жалоба пользователя «выбираю не то»; после v68 — «немного лучше».

Потери звеньев за 1 с — 5,0 в минуту (15.10: 37,8); доля потерь от неподвижного курсора (`append`) — 13 % (15.10: 93 %). Звенья берёт в основном точка события мыши (58 %) и нажатие (34 %).
- Новое мерцание «у героя»: игрок нажимает на врага, который касается героя; курсор попадает в круг героя (`HERO_CANCEL_RADIUS` 0,42). Событие мыши в этом круге снимает единственное звено (герой — «звено ноль» шага назад, этап H). Следующий кадр `append` снова берёт то же тело — `holdNearest` сравнивает только тела, героя не видит. 32 эпизода, 364 автоматические отмены. - Радуга: потери 22 % на свободном цвете против 6 % (15.10: 70 % против 36 %). Остаток — смены цвета точкой события мыши у края круга (0,97 радиуса); правку не делаем.

## 2. Правило (core — sim)

- Неподвижный курсор (`append`) и точки протяжки (`sweep`) считают героя звеном цепи: если точка в круге героя (`HERO_CANCEL_RADIUS`), они ничего не делают — ни взятия, ни отмены (как у звена в задаче 39).
- Точка события мыши (`full`) не меняется: в круге героя при одном звене снимает его (шаг назад к герою), при двух и больше — ничего.
- Итог для игрока: курсор сполз на героя — цепь из одного звена снята и остаётся снятой, пока курсор не вернётся на тело; мерцания нет.

Детерминизм: ключ `Params.holdHeroLink` (bool, хэшируется). По умолчанию false — прежний путь; журнал без ключа — прежний путь; поход — true в `RT_RUN_FORCED`; песочница — true; панель «Цепь», «Неподвижный курсор у героя ничего не берёт». Новых полей мира нет. Подсветка не зависит от режима точки — не меняется.

## 3. Приёмка

- Node, настоящие команды: нажатие на врага у героя, курсор неподвижно в круге героя 60 кадров — с ключом цепь пуста во всех кадрах после первой отмены и не мигает (0 повторных взятий); без ключа — мерцание воспроизводится. Курсор вернулся на тело — тело взято. Ключ false и журнал без ключа — прежний хэш; повтор логов 16.10.2026 без ключа — прежние хэши.
- Скрипт помощника (`control.mts`, рабочая папка дизайна) на синтетическом бою: эпизодов мерцания у героя — 0 с ключом.
- Playwright один раз, настоящая мышь: нажать на врага, касающегося героя, сдвинуть курсор на героя и держать 1 с — цепь пуста и не мигает; вернуть курсор на врага — взят.
- Доки: `docs/realtime-prototype.md` (неподвижный курсор), README при необходимости.
- Плейтест: «выбираю не то» — стало ли меньше; отмены у героя в сводке боя.

## 4. Решение по ходу (16.10.2026, вопрос core)

Правило «`full` не меняется» оставляло мерцание: после шага назад цепь пуста, и следующее событие мыши в круге героя снова берёт тело (контрфакт на логах 16.10: 141 отмена, 122 повторных взятия). Решение — расширить: с `holdHeroLink` точка события мыши (`full`) в круге героя при **пустой** цепи тоже ничего не берёт. Снятие одного звена и «ничего» при 2+ звеньях — как было. Нажатие (`begin`) не меняется: нажатие на врага у героя берёт его. Протяжка из круга героя на тело берёт, как только точка вышла из круга.
- Проверка core (16.10.2026): контрфакт событий мыши логов 16.10 с ключом — 3 повторных взятия у героя (без ключа 348), все на 0,424–0,476 от героя, то есть уже вне круга: герой сдвинулся из-под курсора. Синтетика 6 арен × 3 seed: 9 эпизодов против 3080. Решение дизайна: остаток допустим, гистерезис круга не делаем; смотреть в плейтесте.
