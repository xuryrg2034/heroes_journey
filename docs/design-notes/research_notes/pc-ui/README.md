# Концепт интерфейса для ПК

**Идея от Codex, 19.10.2026. Игровой UI не изменён.**

**[Открыть интерактивный макет](index.html)** · [полный дизайн-разбор](../../codex-idea-pc-ui.md) · [галерея экранов](overview.html).

Открой `index.html` в браузере прямо с диска. Сервер не нужен. Вверху переключаются восемь экранов; кнопка «Сейчас / предложение» показывает исходный кадр для сравнения. «Пример прогноза» демонстрирует информационную карточку в бою. `?present=1#reward` скрывает служебную панель для просмотра конкретного экрана.

Можно попробовать:

- Пробел → Esc отменяет прицел; ещё Esc открывает паузу. I открывает сборку, Esc возвращает назад. Поиск фильтрует предметы.
- Выбор формы меняет сравнение. Применение происходит отдельной кнопкой.
- Узел карты выделяется до нажатия «В бой». Кнопки доступны через Tab и Enter.
- Покупка обновляет запас/ресурсы; лечение на карте увеличивает цену следующей покупки.
- Смена героя в Очаге меняет описание; кнопки жителей раскрывают их назначение.
- Настройки изменяют текст карточек, контраст и переходы кнопок.

Это макет компоновки и взаимодействий: статичный кадр поля, условный граф карты, демонстрационные значения. Боевой симуляции, полного потока даров/событий, покупок NPC, реальных сохранений и игровых настроек здесь нет. Переход «В поход» сокращён до примера карты; смена экранов через верхнюю панель не является прохождением. Изображения «Сейчас» и предложения могут показывать разные подготовленные сборки — сравнивается устройство экрана, не баланс одной партии.

Макет использует изображения персонажей/Очагa из `public/art` относительными ссылками. Для переноса на другой компьютер нужны папка проекта с этими изображениями или сохранённые PNG ниже.

## Проверки, выполненные 19.10.2026

`node docs/design-notes/research_notes/pc-ui/verify-prototype.mjs`

64 сочетания: 8 экранов × 2 размера окна × 2 размера текста × видимость панели просмотра. Проверены выход основных кнопок за границы окна, горизонтальное переполнение, загрузка изображений, ошибки JS и пять групп интерактивных сценариев. Скрипт обновляет PNG и [prototype-evidence.json](prototype-evidence.json). Он проверяет отдельный макет, не игру. Не доказывает отсутствие любого перекрытия текста, удобство наведения в настоящем бою или соответствие всем требованиям доступности. Основные экраны дополнительно просмотрены глазами.

## Аудит существующего UI

- [capture-current.mjs](capture-current.mjs) — обычный путь нового профиля: старт → дар → карта → бой → результат. Для показа результата используется существующий тестовый хук победы; его время/счёт не являются плейтестом.
- [capture-dense.mjs](capture-dense.mjs) — подготовленные моделью состояния: большая сборка, награда, торговец, открытые герои и лагерь. Запуск: `node --import tsx docs/design-notes/research_notes/pc-ui/capture-dense.mjs`.
- Оба скрипта ожидают локальный Vite на `http://127.0.0.1:5189/`, используют изолированный профиль Chromium и перехватывают отправку телеметрии. `npm exec vite -- --host 127.0.0.1 --port 5189 --strictPort` запускает сервер.
- [current-evidence.json](current-evidence.json), [dense-evidence.json](dense-evidence.json) — текст/геометрия проверенных экранов.
- `current-home-1280.png` — дополнительный кадр первого запуска **пролога**, несмотря на первоначальное техническое имя файла.
- `field-only.png` — кадр текущей песочницы без DOM-панелей, снятый браузером для размещения предложенного HUD. Он не изображает новый дизайн арены.

Все `current-*.png` относятся к срезу рабочего дерева 19.10.2026. Составы и численные состояния в предложениях служат иллюстрациями. Источники и ограничения декомпиляции референсов приведены в основном документе.
