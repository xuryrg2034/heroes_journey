## 4. Правила спойлеров

1. **Глава уровня скрыта, пока герой туда не дошёл.** Видна одна пустая вкладка без имени для **следующего** уровня («…»). Дальше — ничего **[П]**, вопрос 2. Лес открыт сразу. Гарнизон — после первого входа в гарнизон (`level 2` в рекорде любого героя). Замок — после первого входа в замок (задача 55).
2. **Числа — только для видимого.** «Записано 41 / 58» считает видимые главы. Новая глава прибавляет к «всего» — книга «толстеет». Это само по себе сюрприз.
3. **Невиденное — пустая карточка «?».** Силуэт — только у боссов (имя на карте уже есть) и у Ведуньи после клетки.
4. **Подсказка — место, не вещь.** Ветка, уровень, тип узла, номер ступени. Не имя врага, не имя события, не правило предмета.
5. **Запертое наборами** — замок без имени; число входит во «всего» (силуэты набора уже стоят у костра).
6. **Нет записи без содержания в сборке.** Каталог Летописи собирается из каталогов кода (раздел 7.3).

## 6. Крючки удержания

### 6.1. Подсказка Неясыти (честная)

- **Когда.** Не чаще одного раза за визит в лагерь, в облачке Неясыти. Только если у прошлого похода нет более конкретного повода (смерть, рекорд, задание, покупка) — правило выбора реплик v1 **[Д]**.
- **Кандидаты.** Чистая функция core `rtChronicleHint(profile, hero)`. Кандидат — пустая запись, которую можно получить **в этой сборке, этим героем, сейчас**:
  - событие не видено и не заперто → место: ветка («ветка Тролля», «ветка Главаря», «тропы после Тюремщика», «любая ветка»);
  - босс уровня, куда герой дошёл, не встречен → «финал ветки Тролля» / «ветки Главаря»;
  - вид гарнизона не встречен (гарнизон открыт) → «в гарнизоне»;
  - сплав: взята одна часть рецепта → имя этой части (её игрок знает) и «пару ищи у Тюремщика» (формы — с экрана Тюремщика) или «на „Заставе“» (редкое место);
  - следующая ступень «Испытания» после лучшей (лестница открыта) → «ступень VI»;
  - NPC не пришёл → строка о поводе без имени NPC («кто-то в лесу ждёт помощи у раненого зверя» — Марфа; «точильщик бродит по тропам» — Ерофей).
- **Не кандидаты:** запертое наборами; скрытая глава (замок до входа); предмет, который герою не предлагают («Печать» Ведунье).
- **Выбор.** Кандидаты в порядке каталога; индекс — номер похода зрителя (`RtProfile.runs`) по модулю числа. Без `Math.random`. Цель уже видена — подсказка о ней больше не звучит.
- **Тексты.** Около 12 строк, 4–16 слов, книжная манера Неясыти («страница», «глава», «записала»). Пишет сессия npc-lines в `npc-lines-v2.md` (новый раздел); метка героя — как v2.1. Образцы (черновик):
  - `hint_event_den` — «На ветке Тролля есть страница, которой у меня нет. Сходи и прочти её мне.»
  - `hint_boss_camp` — «Финал ветки Главаря я ещё не рисовала. Перо сохнет.»
  - `hint_fusion` — «„Иней на клинке“ просит пару. Пару таким выдаёт Тюремщик.»
  - `hint_ash` — «Ступень VI — пустая строка. Не люблю пустые строки.»
  - `chronicle_first` — «Моя летопись. Бестиарий — первая глава, дальше пусто. Пока.»
  - `chronicle_retro` — «Старые страницы размыло дождём. Что помню — вписала, остальное пиши заново.»
- **Честность.** Подсказка не обещает награду. Она говорит только «здесь бывает то, чего ты не видел».

### 6.2. Прочее

- **Книга толстеет.** Вход в гарнизон открывает главы на трёх страницах сразу. Строка конца похода: «В летописи: +1 глава · Гарнизон» **[Д]**.
- **Полная глава** — заголовок главы с отметкой «полна» (чернильная клякса-печать рядом с числом). Ничего не даёт **[Д]**.
- **Трофеи (задача 51е)** — не дублируем: Летопись не показывает трофеи. Трофей «Чернильница Неясыти» ставится по главе «Лес» Бестиария из `chronicle.kinds` (не по `profile.seen`, который сбрасывает «Обучение»).

## 7. Данные (core)

### 7.1. Профиль: `meta.chronicle` (новое, необязательное)

```ts
interface RtChronicle {
  /** Виды KIND_CAPTIONS, встреченные в бою мета-похода (и ретро). Сортировано. */
  kinds?: string[];
  /** Аффиксы элит (AFFIX_IDS). Сортировано. */
  affixes?: string[];
  /** Боссы: номер похода зрителя (RtProfile.runs; 0 — неизвестен, ретро) первой встречи и первой победы. */
  bosses?: Partial<Record<'jailer' | 'troll' | 'castellan' | 'chief' | 'warlock', { met: number; won?: number }>>;
  /** События: id forestEvents и 'casino'. Сортировано. */
  events?: string[];
  /** Предметы: 1 — видел (на экране выбора), 2 — взял. */
  items?: Record<string, 1 | 2>;
  /** Сплавы: сделаны. Сортировано. */
  fusions?: string[];
  /** Записи с прошлого открытия Летописи: 'kind:lynx', 'event:brook', 'item:prism', 'boss:troll', 'hero:toad', 'ash:cat:5', 'npc:herb', 'chapter:garrison'. */
  unread?: string[];
  /** Номер похода зрителя, с которого Летопись пишет (ретро — до него). */
  since?: number;
}
```

- Каждое поле отсутствует, пока пусто. Нет ни одного — нет `chronicle`. Профиль без него читается и пишется как раньше.
- `parseRtMeta` читает поле: неизвестные id отбрасывает (каталог, раздел 7.3), счётчики — целые ≥ 0.
- Герои, «Испытание», NPC в `chronicle` не копируются — читаются из `freed`, `ashBest`, `hearth.met`. В `unread` они попадают в `rtApplyMeta` в момент изменения.
- **«Обучение» Летопись не трогает** **[Д]**: это запись, не состояние обучения.

### 7.2. Кто пишет

- **Конец похода** (`rtApplyMeta`, только мета-поход; повтор того же похода — тот же результат по `applied.key`): события, предметы (видел / взял), сплавы, боссы — из `RtRunState` (раздел 2). Брошенный поход пишет так же.
- **Виды и аффиксы — вариант А (рекомендую) [Д].** Вид вызывает новый метод профиля `chronicleMeet(kinds, affixes, seed)` там, где память П8 встречает вид (`meetKind`, `meetAffix`) в бою мета-похода, — по образцу `meetSchedule`. Сохранение похода и запись боя не меняются. Поход `?seed=` не пишет.
  - Вариант Б: новое поле записи боя `RtBattleRecord.kinds?` (виды и аффиксы боя, отсутствует при пустом). Чище для повтора по журналу шагов (51з), но меняет сохранение похода. Брать, если core захочет одну точку записи.
- **Ретро-импорт.** При первом открытии лагеря после выхода задачи вид вызывает `chronicleImport(память П8)`; core объединяет с `profile.seen` (виды, `affix:<id>`), `freed`, `wonLevel`, ставит `since` и `unread: []` (ретро не считается «новым») и пишет реплику-повод `chronicle_retro` (раз за профиль).
- **Прочитано.** `chronicleRead()` очищает `unread` при открытии Летописи.

### 7.3. Каталог Летописи

- `run/chronicleCatalog.ts` (core, лист без импорта вида): id записей по страницам и главам, уровень главы, ветка события, редкость предмета, рецепты. Собирается из каталогов кода: `SCHEDULE_KINDS` и id видов гарнизона (из `sim/enemies`, не из `KIND_CAPTIONS` вида), `AFFIX_IDS`, `FOREST_EVENTS`, `RT_TALISMANS` (без `RT_TALISMANS_OFF`), `RT_OPENERS`, `RT_FORMS`, `RT_FUSIONS`, `RT_HERO_IDS`, `RT_ASH_MAX`, `RT_HEARTH_NPCS`.
- Боссы — явный список по флагу сборки: Главарь входит в каталог в задаче 54, Колдун и глава «Замок» — в задаче 55.
- Тесты не закрепляют итоговые числа (93): число выводится из каталога. Иначе каждая новая задача ломала бы тесты.

### 7.4. Контракт вида

`rtChronicleView(meta, seen, hero) → { total: [have, known]; pages: { id, have, known, unread, chapters: { id, level, state: 'open' | 'blank', entries: { id, state: 'locked' | 'unknown' | 'seen' | 'taken' | 'met' | 'won', run?: number, half?: string }[] }[] }[]; hint?: { key, target } }`.
- Скрытые записи и главы в контракт не попадают — вид не может их показать по ошибке.
- Имена, подписи, рисунки — вид (`KIND_CAPTIONS`, `metaItemCard`, `forestEvent().title`, арт боссов).

## 10. Телеметрия

Поля записи похода (`RunRecord`, необязательные, только мета-поход):
- `chronicle`: `{ added: string[]; pages: Record<pageId, [have, known]> }` — новые записи похода и счёт после него.

Лагерь (к кликам NPC задачи 37):
- `chronicle-open`: страницы, которые открыл, время в окне (с), был ли «✦».
- `hint`: ключ и цель подсказки, показанной в визите.

Раздел отчёта `npm run realtime:report` — «Летопись»:
- доля каждой страницы (`have / known`) у зрителей по номеру похода: 1–3, 4–10, 11–20, 21+;
- номер похода первой записи гарнизона, первого сплава, первого босса-финала по веткам (Тролль, Главарь);
- доля визитов в лагерь, где Летопись открыта; доля с «✦», которые открыли;
- подсказка → следующий поход дошёл до места цели (ветка, уровень, привал) — доля;
- доля записей «видел, не взял» среди предметов (не тянет ли игрок одну сборку).

Тревожно (эвристика до плейтеста): Летопись открывают < 15 % визитов — её не видно или она скучна; подсказке следуют < 10 % — тексты пустые; > 70 % — подсказка ведёт маршрут сильнее выбора игрока; к 20-му походу «Талисманы и формы» < 50 % «взял» — пулы не дают пробовать (вопрос к сборкам, не к Летописи).

## 11. Приёмка

Тесты — на настоящих походах API и настоящем вводе. Не утверждать победу или поражение бота.

**Node** (`verify.sh --only meta`, `--only hearth`, новый набор `chronicle`):
- Настоящий поход через шаги API (`metaWalk.testkit`): вход в узел события → запись `event:<id>`; круг гоблинов → `casino`; отказ от талисмана на экране → «видел»; взятый → «взял»; сплав на привале → `fusions` и обе части «взял»; бой Тюремщика выигран → `bosses.jailer.won` с номером похода; бой Тролля проигран → `met` без `won`; гарнизон до Кастеляна → `castellan`.
- Поход `?seed=` — `chronicle` не меняется; песочница и пролог — не пишут.
- Брошенный поход пишет; второй `endRunMeta` того же похода — без двойной записи.
- `resetSchedule` («Обучение») не опустошает `chronicle`.
- Старый профиль без поля читается и пишется байт в байт до первого конца мета-похода или импорта.
- Ретро на фикстурах профилей: `seen` + память П8 + `freed` + `wonLevel 2` + `ashBest` → точные записи; профиль с `won` без `ashBest` → лестница 0; лес пройден без ветки → Тролль «?».
- Скрытое не утекает: до входа в гарнизон в контракте нет записей гарнизона; глава следующего уровня — `blank` без записей; запертое наборами — `locked` без имени.
- Подсказка: на нескольких профилях (разные `runs`, разные пробелы) — разные цели (разнообразие, совпадения допустимы); цель всегда получаема (не заперта, уровень открыт, предмет герою предлагают); та же входная пара — та же подсказка; видена — не повторяется.
- Сохранение похода, журналы и хэши не меняются: `verify.sh --only rt-run` (сохранения похода без новых полей — байт в байт).

**Playwright один раз** (`tests/realtime-chronicle.spec.ts`, `NO_PROXY`, конфиг реального времени, настоящая мышь):
- Чистый профиль → поход до события и смерти → строка «В летописи: +N» на экране конца → «В лагерь» → «✦» у Неясыти → клик → «Летопись» → страница «Бестиарий»: встреченные виды с именами, остальное «?»; «События» 1 / 15; Esc закрывает; «✦» пропал.
- Экран конца и облачко Неясыти изменились — один раз `tests/realtime-run.spec.ts`, `realtime-actionbar`, `realtime-heal`. Тесты, которые жмут `hearth-bestiary`, — чинить маршрут на «Летопись», не ожидания.

**Снимки 1280×720 мне:** Летопись в первом лагере (все шесть страниц); Летопись после гарнизона; строка конца похода; «✦» у Неясыти; карточка «?» сплава с половиной рецепта.

## 14. Риски

- **Чек-лист вместо удивления.** Счёт может превратить игру в обход списка. Меры: нет награды за полноту; скрытые главы; подсказка — раз за визит; «?» без силуэта.
- **Спойлер числом.** «/ 18» говорит о размере контента. Меры: число только видимых глав; следующий уровень — пустая вкладка без числа.
- **Потеря у старых тестеров.** Ретро неполное — может читаться как «стёрли прогресс». Мера: реплика `chronicle_retro`; точное ретро всего, что есть.
- **Две памяти видов** (П8 вида и профиль) расходятся. Мера: Летопись — объединение и только растёт; бестиарий читает её.
- **Подсказка ведёт маршрут.** Игрок идёт по подсказке, а не по своему выбору. Мера: телеметрия доли (раздел 10); подсказка о месте, не о награде.
- **«Видел» недосчитан.** Если экран выбора не пишет отказ в `talismansGone`, «видел» теряется. Мера: в счёт идёт «взял»; core перечисляет экраны в 58а.
- **Числа растут с задачами 54, 55.** Тесты на итоговые числа ломались бы. Мера: числа из каталога (раздел 7.3).
- **Тесты на `hearth-bestiary`** сломаются. Мера: чинить маршрут на «Летопись».
- **Окно 1280×720.** 36 карточек на странице предметов — на пределе. Мера: карточка 88×104, 10 в ряд; если не входит — главы страницы вкладками второго уровня, не прокрутка **[Д]**.
