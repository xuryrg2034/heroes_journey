Источник: жалоба пользователя 15.10.2026 «частенько выбираю совсем не то» (радуга, «Развилка»); после задачи 34 (v58) — «не скажу, что что то поменялось». Разбор: `reports/Контроль цепи — разбор логов.md` (26 боёв людей, все повторы = endHash; эвристика, один тестер).

Причина (данные отчёта):
- Неподвижный курсор (`holdPicks`, режим `append`) — вид зовёт его каждый кадр, пока кнопка зажата. `pick` в `append` не видит звеньев цепи и берёт любого кандидата в круге ×1,65.
- Курсор стоит на последнем звене → `append` берёт соседнее тело (в 67 % взятий к курсору ближе было звено цепи) → следующее событие мыши (`full`) на прежнем звене — шаг назад → следующий кадр `append` берёт снова. «Мерцание»: 824 эпизода, 97 % шагов назад сразу отменены; 27 % отпущенных цепей несут такое звено.
- `append` берёт 62 % звеньев и даёт 93 % звеньев, потерянных за 1 с. На радуге кандидатов в 4,5 раза больше (медиана 9 против 2), потери 70 % против 36 %.
- Протяжка за весь лог не взяла ни одного звена (мышь смещается ~0,02 за событие, шаг протяжки 0,15). Задача 34 сняла только смену цвета через `append` — около 20 % потерь.
Вывод: это дефект пути ввода, не баланс. «Выбираю не то» — главным образом тело, которое неподвижный курсор подхватил рядом с последним звеном.

=== ЗАДАЧА 39 «Неподвижный курсор берёт ближайшее» (core — sim; ui — вид). Срочно: перед 36/37 в очереди слияния. ===
Правило (sim):
- В режиме `append` точка курсора выбирает БЛИЖАЙШЕЕ к ней тело среди допустимых кандидатов И звеньев цепи (как `full`). Если ближайшее — звено цепи (любое), ничего не происходит: ни взятия, ни обрезки (append не обрезает, как раньше).
- Новое тело `append` берёт, только если оно ближе к курсору, чем любое звено цепи в круге нажатия.
- Остальное не меняется: `full`, `sweep`, нажатие, `shiftAtPointer`, шаг назад.
Ключ: `Params.holdNearest` (bool, хэшируется). По умолчанию false — прежний путь; журнал без ключа — прежний путь; поход — true в `RUN_FORCED`; песочница — true; панель «Цепь», «Неподвижный курсор берёт ближайшее». Новых полей мира нет.
Подсветка = исполнение: подсветка не зависит от режима точки; проверить, что повтор журнала с ключом даёт тот же хэш в Node и браузере.
Вид (ui, без Params):
- Кольцо «что возьмётся сейчас»: пока кнопка зажата, одно яркое кольцо на теле, которое `pick` взял бы в этой точке курсора (та же функция sim, без копии правила); на звене цепи — ничего. Это ответ на «не вижу, что возьмётся». Тонкое, цвета цепи, не путать с радужным кольцом и кольцами кандидатов.
- Кольца кандидатов — не меняются.
Приёмка:
- Node, настоящие команды: курсор неподвижно на последнем звене, рядом кандидат в круге ×1,65 — с ключом не берётся ни в одном кадре (60 кадров), без ключа — берётся (воспроизводит дефект); курсор ближе к кандидату, чем к звену — берётся; повтор человеческих логов 15.10.2026 без ключа — прежний хэш; число «мерцаний» по скрипту отчёта на синтетическом бою — 0 с ключом.
- Playwright один раз, настоящая мышь: собрать 3 звена, остановить курсор на 3-м и держать 1 с рядом с другим врагом — цепь осталась из 3; сдвинуть курсор на врага — взят.
- Снимок 1280×720: кольцо «что возьмётся».
