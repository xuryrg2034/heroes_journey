=== ЗАДАЧА 31 «Огонь от трёх звеньев» (core — sim; ui — вид). После задачи 28. ===
Правило:
- Путь прохода загорается, только если проход дошёл до 3-го вражеского звена. Счёт звеньев — как у «Взрыва на конце» (`ChainEnd.links`: убитые, пропущенные погибшие по пути, выживший на конце; кристаллы, жаровни, кнопки, дверь, добыча не считаются).
- Когда проход дошёл до 3-го звена, загорается весь путь от начала прохода, не только хвост. Дальше огонь горит как сейчас: `FIRE_LIFE`, `FIRE_DAMAGE`, `FIRE_PAUSE` без изменений.
- Цепь короче 3 звеньев — огня нет, события `hammer` нет.
- Числа огня не трогаем. Порог — единственное изменение.
Детерминизм:
- Ключ `Params.fireMinLinks` (хэшируется). Журнал без ключа — прежний путь (огонь на любой цепи, порог 1). По умолчанию 3. Поход ставит 3 в `RUN_FORCED`. Панель: группа «Талисманы», «„Огненный проход“: звеньев от», 1–6. Урок `endBlastMinLinks`: порог — ключ, не константа.
- Как держать путь до порога (точки ждут или путь копится в состоянии модуля) — решает core. Новых полей мира нет, пока молота нет.
- Подсветка = исполнение: `planChain` знает, дойдёт ли проход до 3-го звена. Подсветка показывает, загорится ли путь.
Ui:
- Подсветка цепи: при 3+ звеньях путь в подсветке — с огненным краем; при 1–2 — без него. Прогресс в колонке сборки — как у «Взрыва на конце» (до 3).
- Момент, когда проход дошёл до 3-го звена: весь пройденный путь вспыхивает разом. Это главный знак правила; текста нет.
- Карточка молота: «Цепь из 3+ звеньев: путь прохода горит 2 с, огонь бьёт врагов на 1 при входе». Имя прежнее.
Приёмка:
- Node: журнал без ключа — прежний хэш (журналы с огнём из логов 15.10.2026, бои f04–f07 похода rmv9ckjsn-f4dd4f6c). С ключом: цепь из 1 и 2 звеньев — ни одной точки огня; из 3 — горит весь путь от начала; подсветка до отпускания = итог на настоящих командах.
- Playwright один раз, настоящий ввод: цепь из 2 звеньев с молотом — огня нет; из 3 — путь горит.
